# 분리 미디어의 발급·사용량 기반

[S15P21C204-215](https://ssafy.atlassian.net/browse/S15P21C204-215)의 발급 기반 단계다.
브랜치는 `feat/S15P21C204-215-split-media-authority`, 기준은 선행 회수 reader가 병합·배포된
`9a4d9ecb`다. [웹 연결](split-media-runtime.md)과 [내구 회수](split-media-recovery.md)에 이어
실제 세대 할당·JWT 서명·파일 예약을 구현한다. 제품 조립부의 공개 모드 선택은 다음 단계다.

## 발급과 불변 소유 범위

`MediaGenerationRegistry`의 명시적인 split 모드는 첫 발급 때 최대6명의 명단을 고정한다.
공유 얼굴 방1개와 각자의 개인 음성 게시/수신 방을 만들고, 각 세대에 두 원본 신원과 최대5개
다른 수신 방을 기록한다. 명단 밖 참가자를 같은 미디어 인스턴스에 추가할 수 없다.
세대 교체 시 방은 유지하되 두 신원을 모두 새로 만들며 종료한 인스턴스의 방 배정을 해제한다.

`GrantIssuer`는 사용량 전체 예약 → 전체 소유 기록의 내구 저장 → 두 서명 → 최종 재검사 후
하나의 공개 grant를 반환한다. 얼굴 JWT는 CAMERA 게시와 수신 불가, 개인 방 JWT는 MIC 게시와
수신 허용이다. 데이터 게시·관리 권한은 없고 두 토큰의 만료 시각은 같은 절대 시각이다.
두 번째 서명 실패·늦은 응답·입장 차단·기한 초과에는 반쪽 grant를 반환하지 않고 전체를 회수한다.

분리 capability는 별도 두 최소 권한 프로필과 실제 제품 전송, 소스 분리, 직접 음성 차단,
동일 목적지 재허용, 수신 SID 대조, 미입장 토큰 거절, 늦은 전달 봉쇄, 내구 복구와 사용량 예약의
확인을 모두 요구한다. 다른 모드의 보고서를 이름만 바꾸거나 권한을 넓힌 프로필은 거절한다.
이 형식의 존재와 시험용 true 값은 실제 Cloud 증거가 아니다.

## 사용량 예약

기존 내구 `UsageRequest.slots=6` 형식을 유지한다. split 세대는 두 원본과 모든 가능한 전달본을
포함한 자원 수를6자리 블록으로 올림하여 먼저 예약한다. 6명일 때 플레이어당12자리, 경기당
72자리를 보수적으로 계산한다. 이는 Cloud의 실제 복제 참가자 과금 방식에 대한 주장이 아니다.

각 블록의 첫 예약은 같은5분 구간이며, 이후 같은1분 구간을 갱신한다. 두 블록을 확보해도
사용 가능한 시간이10분으로 늘지 않는다. 164kbps·목적지 수·시간으로 트래픽을 추정하고,
UsageBudget이100% 여유를 추가한다. 기존 단일 방의6명 공유 예약 방식은 유지한다.

후속 블록이 거절되면 먼저 성공한 예약을 보존하고 발급을 중단한다. 디스크 기록 여부가
불확실한 예약도 회수 경로에 남긴다. 같은 개인 방의 예약을 다른 인스턴스나 확대된 목적지
목록에 재사용하지 않는다. 확인된 회수 후에만 모든 블록을 닫고 다음 예약을 생성한다.

다음 [서버 제어 조립](split-media-policy.md)에서 아래 코드 경로를 연결하며,
실제 provider 인수 전에는 공개 설정을 열지 않는다.

아래가 연결되기 전에는 전체215·W02·PUBLIC_READY를 완료로 계산하지 않는다.

1. MediaCoordinator의 split 선택, 물리 자원 상한, 전체 소유 대조·방 공유/삭제·세대 축약.
2. 서버 가청 정책의 실제 forward/remove, 원본/수신지의 SID와 trackSID 대조.
3. 종료 시 진행 중인 전달의 봉쇄와 늦은 성공의 후처리. 로컬 응답을 버리는 것만으로 끝내지 않는다.
4. 두 연결을 함께 확인하는 서버 lifecycle, HTTP/Room/웹 Runtime과의 최종 제품 조립.
5. 실제 제품 Cloud에서 미입장·지연 전달·부분 실패·교체·재기동·사용량·최종 부재 확인.

환경 설정은 여전히 `server-forwarding` 및 public+livekit을 거절한다. 운영은 팀 SSO와 기존
내부 모드를 유지한다. 현재100참가자 한도에서10경기의 실제 SDK 연결120개부터 한도를 넘으므로
용량 조건과 실제 장치·G1·10방 인수는 별도로 남긴다.
