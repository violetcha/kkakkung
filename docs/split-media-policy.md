# 분리 미디어의 서버 가청 제어

[S15P21C204-215](https://ssafy.atlassian.net/browse/S15P21C204-215)의 제품 조립 단계다.
브랜치는 `feat/S15P21C204-215-split-media-policy`, 기준은 !141 병합·배포112의 `0e50ad3b`다.
[발급·예약 기반](split-media-authority.md)과 [내구 회수](split-media-recovery.md)를 실제
MediaCoordinator의 가청 판정·연결 수명·자원 상한·방 정리에 연결한다.

## 제품 경로

MediaCoordinator가 명시적인 server-forwarding 구성에서 split 세대를 선택한다.
두 원본이 연결됐는지 확인한 다음, SplitMediaPolicyBindings가 서버 TrustedMediaFrame과
AudibilityPolicy를 사용해 얼굴과 허용된 음성만 개인 수신 방에 전달한다. 거리 밖의 음성은
원격 remove ACK와 실제 부재로 차단하며 얼굴 전달은 유지한다. 클라이언트의 publisher 허용
목록이나 updateSubscriptions를 이 모드의 권한 근거로 사용하지 않는다.

ForwardedMediaEdge는 원본의 신원·SID·트랙을 전달 전후에 재조회하고 수신 방의 실제 SID/트랙을
별도로 확인한다. 원본과 clone의 SID가 같다고 가정하지 않는다. 허용되지 않은 소스·트랙 추가·
원본 재입장·예상하지 못한 clone SID 변경은 연결을 회수한다. 서명된 webhook은 조회 계기이며
권한이나 트랙의 존재를 직접 증명하지 않는다. 같은 통지는 전달을 중복 생성하지 않는다.

가청 상태 또는 트랙이 바뀌면 이전 전달을 정리한 뒤 새 전달을 만든다. 허용→차단→재허용이
응답 대기 중에 일어나도 이전 요청을 최신 허용으로 재사용하지 않는다. 수신 바인딩이 확인된
트랙만 웹 AudioPolicy/MediaBindings로 보내며 얼굴의 별도 게시자 SID를 유지한다.

## 종료·복구와 사용량

새 전달은 종료와 동시에 차단한다. 이미 전송한 HTTP 요청은 로컬 취소로 끝났다고 계산하지
않는다. RetirementBarrier는 원본을 먼저 회수하고, 해당 세대가 송신자 또는 수신자인 진행 중
전달이 정리될 때까지 기다린 뒤 최종 부재를 확인한다. 늦은 성공으로 생긴 clone도 정리한다.

원격 forward의 처리 결과 자체가 불명확한 경우에는, 이후 한 번의 부재만으로 성공을 추정하지
않는다. 현재 프로세스의 해당 세대를 UNRESOLVED로 보존하고 예약 해제·새 입장을 막는다.
재기동 복구의 실제 provider 경계는 별도 Cloud 인수가 필요하다. 알 수 없는 처리를 성공으로
바꾸기 위해 journal을 지우거나 capability를 임의 승격하지 않는다.

생명주기 복구는 얼굴/개인 방의 두 SID가 유지되고 두 연결의 최신 조회가 모두 완료돼야 한다.
개인 방 한쪽만 연결되거나 얼굴 SID가 바뀌면 같은 세대가 복구됐다고 인정하지 않는다.

발급 상한은 논리 플레이어 수 대신 두 원본과 가능한 전달본을 포함한다. 고정 명단에서
다음 세대의 자원 수를 계산해 선점하고, 내구 REVOKED를 확인한 자원만 상한에서 뺀다.
6인일 때 가능한72개 자원을 보수적으로 계산하며 실제 provider의 clone 과금 방식과 구분한다.
공유 얼굴 방/개인 수신 방은 그 방의 모든 소유 세대가 확인된 뒤에만 삭제한다.

## 검증과 남은 인수

관련4파일70개 시험이 통과했다. 실제 제품 factory/JWT/서명된 webhook과 journal/checkpoint/
usage budget을 사용하며 Cloud transport만 제어한다. 6인72자원·7방·12예약의 전체 종료,
거리 차단/동일 목적지 재허용, 원본/수신 SID 변경, 부분 연결, 진행 중 전달, 원격 결과 불명확
상태에서 원본 회수·예약 보존·입장 차단, 두 연결 복구를 확인한다. 실제6대나 Cloud 부하 시험은 아니다.
최종 pnpm verify는259파일2,690개·22 E2E(57.8초), 포맷/계약33·도구11/lint/타입/
빌드/실제 Worker·자산 PASS다. 원격 CI·MR·배포는 후속 확인한다.

소스799f8087의 원격 Jenkins MR121은6인 연결 시험에서12/72자원으로 실패했다.
시험이 개인 방의 가입만 알리고 얼굴 방의 가입 통지를 빠뜨려, 최초 조회가 게시 전에
끝난 환경에서는 얼굴 원본의 부재 사본을 유지했다. 최초 조회를 게시 전에 완료하도록
고정하자 구 fixture의 같은 실패를 재현했다. 두 원본의 실제 서명 통지를 모두 보내도록
고친 뒤 관련2파일21개·QA 타입·변경 lint PASS다. 수정 소스의 원격 전체 CI는 재확인한다.
제품의 조회 주기나 권한 검사를 완화하지 않았다.

그 전에 실행한 전체 검사 두 번은 각각 제품 통합1개가 실패했다. 첫 번째는 기존
RuntimeEvidence가 로컬 시각2ms 역행을 CLOCK_ROLLBACK으로 잠근 기록이다. 두 번째는
continuous 모드 방장 이탈/로비 복귀 후 입장503이며 당시 세부 차단 사유는 미확정이다.
해당 실패 시 readiness·운영 잠금·시각 진단을 추가한 뒤 집중2개와 전체 검사를 통과했다.
이 단계에서 시각 역행 정책이나 입장 차단을 완화하지 않았으며, 간헐 실패가 해결됐다고
보고하지 않는다. 두 실패 로그와 진단 보강 기록은 유지하고 W14 운영 안정성에서 추적한다.

운영은 팀 SSO와 기존 내부 미디어 모드를 유지한다. 환경 parser의 server-forwarding 및
public+livekit 거절은 이 단계에서 제거하지 않는다. 새 경로를 실제 provider에서 검증한
완전한 capability 없이 활성화하지 않으며, 원격 CI/기존 팀 모드 배포 smoke도 이를 대체하지 않는다.

다음 단계는 제한된 같은 호스트 Cloud 진단에서 제품 구성 요소의 미입장 토큰·지연 전달·
내구 복구·사용량을 실제로 검증하고, 해당 관측으로 구성한 capability를 제품 서버/HTTP/웹
경로에서 소비하는 것이다. 시험용 true 값으로 스스로 발급을 허용하거나 이전 후보 결과를
새 제품 경로의 결과로 바꾸지 않는다. 전체 G1·실제6대·10방·동일 이미지 audience 인수는 남는다.
