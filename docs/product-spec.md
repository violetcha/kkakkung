## 1. 제품 목표와 대상

### 1.1 한 문장 소개

까꿍은 웹캠으로 몸과 고개를 움직여 조작하는 6인(도망자 3 · 술래 3) 1인칭 미로 술래잡기다. 경기는 180초이고, 참가자의 가공된 흑백 얼굴이 블록 아바타 머리에 붙으며, 가까운 사람의 목소리만 들린다. 이동·포획·승패는 모두 서버가 판정한다.

### 1.2 핵심 경험

| 역할   | 목표                               | 하는 일                                                                                                                          |
| ------ | ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 도망자 | 도망자 셋 중 둘이 자기 출구로 탈출 | 좁은 시야로 미로를 탐색해 자기 출구를 찾는다. 옆 도망자와 지도를 교환한다. 출구 벽 앞에서 지정된 팔 자세를 1.2초 유지해 탈출한다 |
| 술래   | 도망자 셋 중 둘을 포획             | 같은 칸·맞교차·정면 한 칸의 도망자를 잡기 동작으로 포획한다. 감지기와 덫을 하나씩 설치하고, 과거 사건 흔적을 미니맵에서 본다     |

두 팀 모두 자기 시야(정면 좌우 40도, 3.5칸)만 보며, 가 본 곳은 개인 지도로 남는다. 상대 얼굴은 시야에 들어온 사람에게만 붙는다.

### 1.3 대상과 공개 경로

| 방 종류             | 사람 수                     | 들어오는 길                                              | 누가 들어오나                               |
| ------------------- | --------------------------- | -------------------------------------------------------- | ------------------------------------------- |
| 일반(`match`)       | 6(3:3)                      | 제품 주소에서 방 만들기·방 코드 참가·초대 링크           | 서버 입장 방식에 따라 다름(13.2)            |
| 시연(`showcase`)    | 4(2:2, 역할별 2명)          | `/showcase`에서 자리를 고르면 빈자리 있는 시연 방에 앉힘 | SSO 로그인 + 운영자 이메일 목록에 있는 사람 |
| 데모(`demo`)        | 운영자 1 + 서버 인형 5(3:3) | `/demo` 또는 운영 API                                    | SSO 로그인 + 운영자 목록, 또는 운영 토큰    |
| 혼자 연습(튜토리얼) | 1                           | 홈 입장 창의 `튜토리얼`                                  | 누구나. 서버 방·LiveKit을 쓰지 않는다       |

제품 화면은 `6인 멀티플레이`·`PC · 카메라 필수`를 안내한다.

## 2. 상태 용어

**방 단계**

| 단계             | 뜻                                      | 사용자에게 보이는 것                           |
| ---------------- | --------------------------------------- | ---------------------------------------------- |
| `LOBBY`          | 사람을 모으는 중                        | 대기실. 준비 단추는 잠김                       |
| `DEVICE_CHECK`   | 자리가 다 참. 각자 장치 점검·준비       | 대기실 + 준비 단추, 준비 흐름 창               |
| `TEAM_PRACTICE`  | 역할별로 따로 연습(최대 60초)           | 세계 화면과 연습 과제                          |
| `MAP_FINALIZING` | 서버가 미로 배치를 만드는 중(최대 30초) | 전면 로딩 `미로 준비`                          |
| `GAME_LOADING`   | 모두의 화면·얼굴 연결 확인(최대 30초)   | 전면 로딩 `화면·연결 확인`                     |
| `COUNTDOWN`      | 시작 3초 전                             | 전면 로딩의 카운트다운 숫자                    |
| `PLAYING`        | 경기 진행(180초)                        | 세계 화면과 HUD, 개인 종료 뒤엔 관전 또는 결과 |
| `RESULT`         | 승패 확정                               | 결과 화면과 재경기 선택                        |
| `ABORTED`        | 경기 무효                               | 결과 화면(중단 사유)과 재경기 선택             |

**개인 상태**: `ACTIVE`(참가 중), `ESCAPED`(탈출), `CAPTURED`(포획). 한 번 정해진 개인 결과는 뒤집히지 않는다.

**방 종류**: `match`(일반), `showcase`(시연), `demo`(데모). 팀 연습은 방 종류가 아니라 일반·시연 방의 한 단계이고, 혼자 연습은 서버 방을 쓰지 않는 로컬 체험이다.

근거: [server.md 9.1](impl/server.md#91-상태-기계), [protocol.md 9장](impl/protocol.md#9-enum-값), [web.md 6장](impl/web.md#6-제품-화면-선택).

## 3. 현재 제공 범위

### 3.1 제품 경로에 연결된 기능

- 입장: 방 만들기, 방 코드 참가, 방장 초대 링크, SSO·게스트·초대 입장 방식, 대기방 여유 표시
- 대기실: 자리·준비·연결 표시, 방장 입장 잠금·내보내기·맵 크기 선택, 방 소식 로그, 내 얼굴 타일
- 준비: 카메라 동의(만 14세 이상 확인), 카메라·얼굴 추적·중립 자세 보정·동작 확인, 확인음
- 팀 연습: 역할별 연습 인스턴스, 과제 목록, 같은 역할끼리의 얼굴·음성
- 경기: 서버 권위 이동·회전·잡기·포획, 술래 감지기·덫·구속·면역, 도망자 지도 교환·개인 출구·탈출 도전, 제한시간 승패, 관전
- 미디어: 가공 흑백 얼굴 게시·수신, 거리·모퉁이 기반 음성과 효과음, 친구별 음소거
- 끝: 결과·중단 사유 표시, 재경기(같은 팀·역할 교대·로비), 연결 끊김 안내
- 운영: 데모 방과 22개 대본, 시연 방, 운영 명령(drain·resume·checkpoint·회수 재시도), LiveKit 월 사용량 가드

### 3.2 제공하지 않는 기능

| 기능                                       | 현재 코드                                                                                                                                                                                                                           |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 도망자 아이템                              | 아래 3.3                                                                                                                                                                                                                            |
| 경기 중 재접속                             | 일반·시연 방은 경기(`PLAYING`) 중 끊기면 25초 안에 같은 자리로 자동 재접속한다. 못 돌아오면 경기가 무효다. 데모 방은 자리와 세션을 유지한다(12.3)                                                                                   |
| 대기실에서 다른 사람 얼굴                  | 움직이는 영상은 없다. 대기실·장치 점검에는 미디어가 없다. 준비를 누른 뒤 얼굴이 1초 이상 잡히면 가공 얼굴(흑백·96px JPEG) 사진 한 장을 게임 서버가 같은 방에 전하고, 준비 완료한 사람 자리에 그 사진이 붙는다(S15P21C204-401)(11.2) |
| 서버 분리 전달 미디어(`server-forwarding`) | 코드와 Cloud 시험은 있지만 환경 변수로 켤 수 없다                                                                                                                                                                                   |
| 탈출 자세의 서버 검증                      | 서버는 보고 시각·위치·상태만 본다. 자세가 진짜인지는 확인하지 않는다(10장)                                                                                                                                                          |

### 3.3 도망자 아이템

제품 명령 목록에 도망자 아이템 명령이 없다(`ITEM`·`PICKUP`·`USE_`가 들어간 명령 종류가 없음). 도망자의 핫바는 빈 칸 5개다. 장비 명령 `INSTALL`의 종류는 술래의 `sensor`·`trap`뿐이다.

## 4. 사용자 흐름과 화면

### 4.1 서비스 진입

| 주소                                | 화면                                                              |
| ----------------------------------- | ----------------------------------------------------------------- |
| `/demo`                             | 데모 방 발급(역할·표시 이름, 기본 이름 `관리자`)                  |
| `/showcase`                         | 시연 방 발급(자리 `도망자 1·2`·`술래 1·2`, 표시 이름은 자리 이름) |
| `#demo=…`·`#showcase=…`가 붙은 주소 | 받은 세션으로 곧바로 방에 들어간다. 주소의 fragment는 지운다      |
| `#invite=<토큰>&room=<코드>`        | 초대 링크. 입장 창이 초대 기준으로 열리고 방 코드가 채워진다      |
| 그 밖(`/`, `/play`)                 | 제품 홈                                                           |

개발 빌드에서만 `/preview`(합성 검수 화면)와 진단 화면이 추가로 있다. 배포 빌드에는 두 화면이 들어가지 않는다.

**홈**: 제목 메뉴에서 `시작하기`(입장 창)와 `옵션`(화면·소리·조작 안내)을 고른다. 홈에서는 카메라를 켜지 않는다. 입장 창의 갈래는 `방 잡기`(입장 폼), `튜토리얼`(혼자 연습), `게임 방법`이다.

**입장 폼**

| 항목      | 규칙                                                                                   |
| --------- | -------------------------------------------------------------------------------------- |
| 닉네임    | 1–20자                                                                                 |
| 입장 방법 | `새 방 만들기` / `친구 방 참가`                                                        |
| 방 코드   | 참가일 때만. 6자리, 혼동 문자(I·O·0·1) 없는 대문자·숫자                                |
| 초대 토큰 | 초대 링크로 왔을 때 함께 보낸다                                                        |
| 제출 가능 | 초대 토큰이 있으면 늘 가능. 없으면 SSO 입장은 만들기·참가 모두, 게스트 입장은 만들기만 |

입장 창이 열려 있는 동안 15초마다 `지금 경기 가능 a/b · 대기방 여유 c/d`를 보여 준다. 점검 중이거나 대기방이 가득 차면 방 만들기를 막는다. 월 사용량 한도나 경기 자리 부족은 안내만 하고 만들기는 허용한다. 참가는 어느 경우에도 막지 않는다.

**입장 오류 문구**

| 코드                 | 문구                                                                            |
| -------------------- | ------------------------------------------------------------------------------- |
| `INVALID_REQUEST`    | 닉네임·초대 링크·방 코드를 확인해 주세요.                                       |
| `INVALID_INVITATION` | 유효한 초대 링크가 필요합니다.                                                  |
| `ROOM_NOT_AVAILABLE` | 입장할 수 없는 방입니다.                                                        |
| `RATE_LIMITED`       | 잠시 기다린 뒤 다시 시도해 주세요.                                              |
| `ADMISSION_CLOSED`   | 지금은 입장을 받고 있지 않습니다.                                               |
| `CAPACITY`           | 지금은 열 수 있는 방이 모두 사용 중입니다. 잠시 뒤 다시 시도해 주세요.          |
| `ROOM_FULL`          | 이 방은 인원이 모두 찼습니다. 방 코드를 확인하거나 새 방을 만들어 주세요.       |
| `TOO_MANY_ROOMS`     | 이미 열어 둔 방이 있습니다. 쓰지 않는 방을 닫거나 잠시 뒤 다시 시도해 주세요.   |
| `ALREADY_IN_ROOM`    | 다른 창이나 탭에서 이미 방에 참가 중입니다. 그 창을 닫은 뒤 다시 시도해 주세요. |
| `INVALID_SESSION`    | 입장 시간이 만료됐습니다. 다시 입장해 주세요.                                   |
| 그 밖                | 연결할 수 없습니다. 로그인과 네트워크 상태를 확인해 주세요.                     |

### 4.2 단계별 경험과 전환

| 단계               | 화면                  | 다음 단계로 넘어가는 조건                                                                                                                                      |
| ------------------ | --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `LOBBY`            | 대기실                | 연결 수가 정원(일반 6, 시연 4, 데모는 운영자+인형 5)에 닿으면 `DEVICE_CHECK`                                                                                   |
| `DEVICE_CHECK`     | 대기실 + 준비 흐름    | 모두 준비한 뒤 방장이 `게임 시작`. 서버 준비·월 사용량·경기 자리를 통과하면 `TEAM_PRACTICE`. 사람이 빠지면 `LOBBY`. 300초가 지나면 미준비자를 내보내고 `LOBBY` |
| `TEAM_PRACTICE`    | 세계 화면 + 연습 과제 | 전원 `연습 준비 완료`면 곧바로 다음. 아니면 60초 뒤, 그때 전원이 장치 준비 상태면 다음, 아니면 `DEVICE_CHECK`                                                  |
| `MAP_FINALIZING`   | 로딩 `미로 준비`      | 배치를 만들면 `GAME_LOADING`. 배치 실패와 30초 초과는 `DEVICE_CHECK`(초과 때 미디어가 걸려 있으면 `ABORTED`)                                                   |
| `GAME_LOADING`     | 로딩 `화면·연결 확인` | 전원이 로딩 완료와 자기 얼굴 트랙 확인을 보고하면 `COUNTDOWN`. 30초 초과는 `DEVICE_CHECK`                                                                      |
| `COUNTDOWN`        | 로딩 카운트다운       | 3초 뒤 `PLAYING`. 15초 초과는 `DEVICE_CHECK`                                                                                                                   |
| `PLAYING`          | 세계 화면 + HUD       | 승패가 나면 `RESULT`                                                                                                                                           |
| `RESULT`·`ABORTED` | 결과 화면             | 방장이 재경기를 고르면 새 경기의 `LOBBY`                                                                                                                       |

`TEAM_PRACTICE`부터 `COUNTDOWN` 사이에 누가 나가면 그 라운드를 버리고 `LOBBY`로 돌아간다. 준비 실패는 대기실에 사유 문구로 나온다.

| 준비 실패 사유            | 문구                                                                                                                             |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `SERVICE_NOT_READY`       | 서버가 아직 경기를 시작할 수 없습니다. 잠시 후 다시 준비해 주세요.                                                               |
| `LAYOUT_UNAVAILABLE`      | 경기장을 준비하지 못했습니다. 모두 다시 준비를 눌러 재시도해 주세요.                                                             |
| `DEVICE_LOADING_TIMEOUT`  | 제한 시간 안에 모든 참가자의 화면·카메라 연결을 준비하지 못했습니다. 장치와 네트워크를 확인한 뒤 다시 준비해 주세요.             |
| `MEDIA_NOT_READY`         | 연습 중 카메라·음성 연결을 준비하지 못했습니다. 장치 연결을 확인한 뒤 다시 준비해 주세요.                                        |

### 4.3 연습

**혼자 연습(튜토리얼)**: 서버 없이 브라우저 안에서 돈다. 15칸짜리 작은 미로에서 도망자로 시작하고, 역할을 바꿔 술래도 해 볼 수 있다. 출구 도전은 `양팔 Y자` 자세, 이동·회전 시간은 서버와 같다(12·8틱). 처음에는 키보드 모드이고 카메라를 켜고 보정하면 모션 모드가 된다. Esc로 체험 메뉴를 연다. 여기서 바꾼 음량·품질은 홈 설정에 저장된다.

**팀 연습**: 일반·시연 방의 `TEAM_PRACTICE` 단계다. 같은 역할끼리 따로 연습 인스턴스에 들어간다. 과제는 `한 칸 전진`(W), `한 칸 후진`(S), `왼쪽 90° 회전`(A), `오른쪽 90° 회전`(D), `중립으로 멈추기`(키 놓기)와 역할 과제(도망자 `탈출 도전`(E), 술래 `장비 설치`(F))다. 연습에는 포획·잡기·팀 승패·제한시간이 없고, 덫은 발동하지 않으며, 출구가 없어 탈출 도전을 시작할 수 없다. `연습 준비 완료`는 장치가 준비됐을 때만 누를 수 있다.

근거: [web.md 9.1·14장](impl/web.md#14-혼자-연습튜토리얼), [game-core.md 3장](impl/game-core.md#3-경기-생성과-상태).

### 4.6 미니맵

- 기본은 내 주변 11칸 창이고, `M` 키로 방 맵 크기(15·23·31칸)의 전체 지도와 오간다(180ms 전환).
- 가 본 바닥과 벽만 그린다. 내 위치는 흰 점과 시선 부채꼴(반지름 3.2칸·폭 90°)이다.
- 도망자는 발견한 출구를 벽 띠로 본다. 내 출구는 금색(`#d9b25a`), 남의 출구는 회색(`#9d9889`)이다.
- 술래에게는 출구를 그리지 않는다. 대신 과거 사건 흔적이 표시 시간 동안 나온다. 덫은 붉은 ▲, 감지기는 노란 ■에 퍼지는 물결 고리가 붙고, 교환은 원이다. 마지막 0.5초에 흐려진다. 작은 창 밖에서 일어난 흔적은 창 가장자리에 그쪽을 가리키는 화살표로 나온다.
- 덫·감지기가 발동하면 거리와 상관없이 모든 술래에게 경보음(감지기 삐삐, 덫 철컥)과 전면 플래시가 나고, 화면 위쪽에 `▲ 덫 작동 · 북동쪽 약 12칸`처럼 종류·방향·거리가 3초 동안 뜬다.

### 4.7 결과와 관전

- 도망자가 탈출하거나 포획되면 그 사람은 경기에서 빠진다. 살아 있는 도망자가 있으면 그 사람의 시점을 관전하고(`생존 도망자가 보고 듣는 범위만 함께 봅니다.`), 없으면 결과 화면으로 간다. 관전자는 명령을 보낼 수 없다.
- 결과 화면은 제목(`도망자 승리`/`술래 승리`/`경기 무효`), 본문, 개인 결과(`탈출 성공`/`포획됨`), 팀 결과(`우리 팀 승리`/`우리 팀 패배`), 집계(`탈출 n · 포획 n · 종료 시 남은 도망자 n`)를 보여 준다.

| 결과                       | 본문                                                               |
| -------------------------- | ------------------------------------------------------------------ |
| 도망자 과반 탈출           | 도망자 N명이 탈출하여 도망자 팀이 승리했습니다. (N은 실제 탈출 수) |
| 도망자 과반 포획           | 도망자 N명을 포획하여 술래 팀이 승리했습니다. (N은 실제 포획 수)   |
| 시간 종료, 도망자 승(시연) | 제한 시간이 끝났고 탈출이 포획보다 많아 도망자 팀이 승리했습니다.  |
| 시간 종료, 술래 승         | 제한 시간이 끝나 술래 팀이 승리했습니다.                           |

## 5. 경기 규칙과 시간

### 5.1 인원과 승패

| 방   | 인원 | 즉시 결과                                | 제한시간 | 제한시간 결과                                 |
| ---- | ---- | ---------------------------------------- | -------- | --------------------------------------------- |
| 일반 | 3:3  | 탈출 2명 → 도망자 승, 포획 2명 → 술래 승 | 180초    | 과반이 없으면 술래 승                         |
| 시연 | 2:2  | 없음. 개인 탈출·포획만 반영              | 180초    | 탈출 수 > 포획 수면 도망자 승, 아니면 술래 승 |
| 데모 | 3:3  | 일반과 같음                              | 없음     | — (운영자가 라운드를 끝낼 수 있음)            |

과반은 경기의 도망자 수 기준 `floor(n/2)+1`이다. 무승부는 없다.

### 5.2 시간과 행동

서버 틱은 50ms다.

| 값                            | 틱       | 시간      |
| ----------------------------- | -------- | --------- |
| 한 칸 이동                    | 12       | 0.6초     |
| 90도 회전                     | 8        | 0.4초     |
| 잡기 창                       | 6        | 0.3초     |
| 경기                          | 3600     | 180초     |
| 장비 설치                     | 10       | 0.5초     |
| 설치 뒤 무장                  | 20       | 1초       |
| 덫 구속                       | 60       | 3초       |
| 구속 뒤 면역                  | 40       | 2초       |
| 지도 교환 제안 유효           | 80       | 4초       |
| 교환 흔적 공개 지연 / 노출    | 20 / 40  | 1초 / 2초 |
| 탈출 도전 최소 / 만료         | 40 / 160 | 2초 / 8초 |
| 도전 실패·취소 뒤 재시도 제한 | 10       | 0.5초     |

단계 시간: 카운트다운 3초, 팀 연습 최대 60초, 미로 준비 최대 30초, 로딩 최대 30초, 카운트다운 최대 15초, 장치 점검 300초.

### 5.3 포획

- 잡기 창이 열린 술래와 도망자가 이동을 마친 뒤 다음 중 하나면 포획이다.
  - 같은 칸
  - 같은 틱에 서로 칸을 맞바꿈
  - 도망자가 술래 정면 한 칸(통로)에 있음
- 측면·대각선·뒤·벽 너머는 포획하지 않는다.
- 구속·면역 중인 도망자도 포획된다. 탈출 도전 중에도 포획될 수 있다.
- 잡기 창은 명령 다음 틱부터 6틱 동안이다. 명령을 보낸 틱에는 포획이 없다.

## 6. 조작·장치·모션

### 6.1 조작표

방에 들어가면 기본은 **모션 모드**다. `키보드로 조작`을 누르거나 카메라 추적이 끊기면 키보드 모드가 된다. 모션 모드에서는 W/A/S/D와 방향키로 움직이지 않는다.

| 행동                | 키보드 모드                   | 모션 모드                     | 누가   |
| ------------------- | ----------------------------- | ----------------------------- | ------ |
| 한 칸 전진          | `W`/`↑`를 180ms 누름          | 몸을 앞으로 기울여 180ms 유지 | 모두   |
| 한 칸 후진          | `S`/`↓`를 320ms 누름          | 몸을 뒤로 젖혀 320ms 유지     | 모두   |
| 계속 이동           | 400ms 넘게 누름               | 400ms 넘게 기울임             | 모두   |
| 90도 회전           | `A`/`←`, `D`/`→`를 150ms 누름 | 고개를 좌우로 돌려 150ms 유지 | 모두   |
| 이동 멈춤           | —                             | `Space`를 누르는 동안         | 모두   |
| 잡기                | `G`(경기 중)                  | 주먹(유지하면 200ms마다 다시) | 술래   |
| 장비 고르기         | `1` 감지기, `2` 덫            | —                             | 술래   |
| 설치 / 설치 취소    | `F`                           | V 손동작 600ms                | 술래   |
| 지도 교환 요청·수락 | `E`                           | 펼친 손바닥 600ms             | 도망자 |
| 탈출 도전 시작      | `E`(자기 출구 벽 앞)          | `E`                           | 도망자 |
| 탈출 자세           | 방향키 네 개를 정해진 순서로  | 지정 팔 자세를 1.2초 유지     | 도망자 |
| 탈출 도전 취소      | `Esc`                         | `Esc`                         | 도망자 |
| 미니맵 축척         | `M`                           | `M`                           | 모두   |
| 설정 창             | `Esc`(방 안, 도전 중 제외)    | `Esc`                         | 모두   |

`E`는 들어온 교환 수락 → 마주 본 내 출구 도전 → 옆 아군에게 교환 요청 순으로 하나만 한다. 고개가 약 12도(0.2094rad) 넘게 돌아가 있으면 전후 이동을 만들지 않는다. 모션 모드에서 입력이 잠겼다 풀리면 몸을 똑바로 세운 채 잠깐(150ms) 있어야 다시 움직인다. 입력창에 글을 쓰는 중에는 게임 키를 무시한다.

근거: [web.md 13장](impl/web.md#13-입력).

### 6.2 장치 준비와 동의

- 카메라는 방에 들어간 뒤 켠다. 홈에서는 켜지 않는다.
- 처음 카메라를 켤 때 `카메라 사용 동의` 창이 열린다. `위 내용을 읽고 동의합니다.`와 `만 14세 이상입니다.`를 모두 체크해야 동의할 수 있다.
- 동의는 개인정보 안내 판 `2026-09-25` 기준으로 브라우저에 저장된다. 판이 바뀌면 다시 묻는다. `2026-09-25` 판은 대기실 얼굴 사진 문장을 더했다(S15P21C204-401).
- 마이크는 선택이다. 마이크만 실패해도 모션 조작은 유지된다.

### 6.3 장치 점검(준비 흐름)

대기실 `준비하기`를 누르면 점검 창이 열리고 카메라가 켜진다.

| 순서 | 안내 문구                     | 통과 조건                                                                    |
| ---- | ----------------------------- | ---------------------------------------------------------------------------- |
| 1    | `카메라를 켜는 중…`           | 카메라 준비                                                                  |
| 2    | `얼굴 추적을 준비하는 중…`    | 얼굴 추적 모델 준비(모델 파일 해시 검사 포함)                                |
| 3    | `정면을 보고 가만히 계세요`   | 중립 자세 보정(신선한 표본 8개, 흔들림 10도 이하). 자동 시작                 |
| 4    | `몸을 앞으로 기울여 보세요`   | 보정 기준보다 앞으로 기울임을 한 번 봄                                       |
| 5    | `고개를 왼쪽으로 돌려 보세요` | 고개 회전을 한 번 봄(방향은 무관)                                            |
| 6    | `확인 완료`                   | 서버에 준비(`READY`)를 보낸다. 소리 재생이 잠겨 있으면 확인음 뒤 다시 보낸다 |

- 카메라나 얼굴 추적이 실패하면 오류 문구와 `다시 시도`가 뜬다. `나중에 하기`는 창만 닫는다.
- 준비한 뒤 장치 조건이 깨지면 준비가 자동으로 취소된다. 팀 연습에서도 연습 준비가 자동 취소된다.
- 데모 방은 일반 방과 같은 점검을 거치고, 마치면 모션으로 조작한다. 카메라 없이 확인할 때만 `카메라 없이 키보드로 준비 (데모)`로 건너뛰며, 이때는 키보드로 조작한다(일반 방에서 카메라가 안 될 때와 같다). 경기 중 `보정 후 모션으로 조작`을 누르면 꺼진 카메라부터 켠다.

## 7. 맵·시야·개인 지도

### 7.1 맵 크기

| 대기실 표기          | 논리 격자 | 템플릿      |
| -------------------- | --------- | ----------- |
| `16x16`(small)       | 15×15     | `maze-s-v1` |
| `24x24`(medium)      | 23×23     | `maze-m-v1` |
| `32x32`(large, 기본) | 31×31     | `maze-v1`   |

- 방장이 대기실에서 크기를 **바꾸면** 그 크기의 템플릿을 쓴다.
- 한 번도 바꾸지 않은 방은 서버 기본 템플릿(`PRODUCT_MAP_TEMPLATE`, 기본값 `maze-v1`)으로 경기한다.
- 시연 방은 크기를 바꿀 수 없고 `16x16`(small)으로 고정해 그 템플릿으로 경기한다.
- 템플릿은 8가지 회전·반전 변형 중 하나를 시드로 고르고, 매 라운드 시드는 새로 뽑는다. 시연 방만 시드가 고정이다. 시연 방은 자리(`/showcase`에서 직접 고른 도망자 1·2, 술래 1·2)마다 시작 칸과 출구도 매번 같다. 누가 먼저 들어오든 고른 자리를 받고, 이미 앉은 자리는 고를 수 없다(S15P21C204-403).

### 7.2 배치 제약

| 제약(31격자 기준)            | 값             |
| ---------------------------- | -------------- |
| 도망자끼리 시작 거리         | 이동 18칸 이상 |
| 도망자·술래 시작 거리        | 18칸 이상      |
| 출구 접근 칸끼리 거리        | 10칸 이상      |
| 도망자 시작 → 자기 출구 경로 | 18–45칸        |
| 세 출구 경로의 최대/최소 비  | 1.3 이하       |
| 시작 칸의 통로 이웃          | 2개 이상       |

31보다 작은 맵에서는 거리 값을 `width / 31` 비율로 줄인다. 세 출구의 탈출 자세는 `왼팔`·`오른팔`·`양팔 Y자`가 하나씩 배정된다. 배치를 만드는 시간은 100ms, 시도는 256회, 한 번에 8개까지이고(튜닝 JSON `selection`), 고른 변형은 통로 연결성을 먼저 검사한 뒤, 실패하면 미리 인증해 둔 폴백 배치를 쓴다.

### 7.3 정보 비대칭

- 도망자는 자기 출발 칸만, 술래는 자기 영역 전체를 처음부터 안다. 둘 다 출발 자세에서 처음 보이는 곳도 안다.
- 이후 본 칸과 벽면이 개인 지도에 쌓이고, 뒤돌거나 경기에서 빠져도 지워지지 않는다.
- 도망자는 출구 벽면을 직접 보거나 교환으로 받아야 출구를 안다. 자기 출구가 어디인지는 모르고 시작한다.
- 술래는 출구를 알 수 없다.
- 탈출 자세 종류는 도전을 시작할 때 본인에게만 알려진다.
- 서버는 각 참가자에게 그 사람이 보는 칸·상대·장비만 보낸다. 장비 소유자는 보내지 않는다. 적 참가자는 경기마다 바뀌는 별칭 ID로 보낸다.

### 7.4 렌더링 기준

| 값                 | 현재                                                                       |
| ------------------ | -------------------------------------------------------------------------- |
| 서버 시야          | 정면 좌우 40도, 3.5칸. 벽을 지나지 않는 칸·벽면만. 대각선 틈으로는 안 보임 |
| 칸 폭              | 1.2m. 칸 단위 값(시야·안개·그리기 거리)은 이 폭을 곱한 거리로 그린다       |
| 눈높이             | 0.8m                                                                       |
| 가로 시야각        | 80도(세로는 화면비로 환산)                                                 |
| 카메라 그리기 거리 | 0.03–3.6칸                                                                 |

안개는 서버 시야(3.5칸) 바로 안쪽인 3.4칸에서 완전히 닫히고 카메라는 3.6칸까지 그린다. 그래서 먼 벽이 그리기 끝에서 잘리지 않고 배경색으로 스며든다.

## 10. 개인 출구와 탈출

- 도망자마다 자기 출구가 하나씩 있다. 출구는 미로 내부 벽의 한 면이고, 접근 칸이 정해져 있다.
- 탈출 도전은 자기 출구의 접근 칸에 서서 그 벽을 정면으로 보고 `E`를 눌러야 시작된다. 접근 칸에 들어가는 것만으로는 아무 일도 없다.
- 도전 중에는 이동·회전·교환이 막힌다. 포획은 될 수 있다.

| 방식   | 할 일                                                                                                 |
| ------ | ----------------------------------------------------------------------------------------------------- |
| 모션   | 화면에 뜬 자세(`내 왼팔 들기`/`내 오른팔 들기`/`양팔 Y자`)를 얼굴과 양 어깨가 보이게 한 채 1.2초 유지 |
| 키보드 | 방향키 네 개를 화면이 보여 주는 순서대로 누름(틀리면 처음부터)                                        |

- 모션 도전 창은 글 대신 그림으로 안내한다(S15P21C204-393). 거울처럼 그린 막대 인형이 자세를, 둘레 링이 1.2초 유지 진행을 보여 준다. 자세가 안 맞으면 옆에 두세 단어(`팔을 더 높이`, `팔을 더 벌리기`, `반대 팔은 내리기`, `한 걸음 뒤로` 등)를 띄우고 인형의 해당 팔에 화살표를 깜빡인다. 혼자 연습도 같은 그림을 쓴다.
- 도전을 시작하고 2초가 지난 뒤에 완료를 보고할 수 있다. 8초 안에 못 끝내면 실패하고 0.5초 뒤 다시 도전할 수 있다. 취소해도 0.5초를 기다린다.
- 탈출하면 그 도망자는 경기에서 빠지고, 출구는 닫힌다.
- 서버는 완료 보고의 시각·위치·방향·상태만 확인한다. 팔 자세가 진짜인지는 브라우저가 판정하고 서버는 확인하지 않는다. 의도한 신뢰 경계다([16장](#16-결정-사항)).

## 11. 얼굴·음성·효과음

### 11.1 실제 얼굴과 로컬 처리

- 카메라 원본(640×480, 최대 30fps)은 브라우저 안에서만 쓰고 보내지 않는다.
- 보내는 것은 전용 캔버스에서 만든 얼굴 영상 하나다.
  - 160×160px, 10fps, 흑백
  - 얼굴 윤곽 안쪽만 남기고 바깥은 검정
  - 인코딩 100kbps(낮은 품질 50kbps·8fps)
- 얼굴을 놓치면 마지막 얼굴을 1.2초 유지한 뒤 기본 그림 얼굴로 바꾼다. 탭을 숨기면 바로 기본 얼굴이 된다.
- 조명·각도 문제는 화면에 안내한다.
  - 고개가 돌아감
  - 안경 반사
  - 역광
  - 가림

### 11.2 어느 단계에서 누구 얼굴이 보이나

| 단계             | 내 화면에 보이는 얼굴                                                                                                  | 음성                                     |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| 대기실·장치 점검 | 내 자리에는 내 얼굴(실시간). 준비 완료한 다른 사람 자리에는 가공 얼굴 **사진 한 장**(미디어 연결 없음, 게임 서버 중계) | 없음                                     |
| 팀 연습          | 같은 역할 연습 인스턴스 참가자 중 시야에 든 사람(수신 최대 2명). 우상단에 내 얼굴                                      | 같은 역할끼리, 거리 기반                 |
| 로딩·카운트다운  | 연결은 되지만 화면은 로딩                                                                                              | 출력 잠김                                |
| 경기             | 시야에 든 상대 아바타 머리(수신 최대 5명). 우상단에 내 얼굴                                                            | 거리 기반(11.3)                          |
| 관전             | 관전 대상 시점에서 보이는 얼굴                                                                                         | 대상 위치에서 듣되 대상 목소리는 안 들림 |
| 데모 방          | 미디어를 쓰지 않는다. 인형은 공통 그림 얼굴                                                                            | 없음                                     |
| 혼자 연습        | 우상단 내 캐릭터 창에 내 얼굴                                                                                          | 없음                                     |

얼굴은 서버가 보낸 참가자 연결표와 트랙 ID가 일치할 때만 붙는다. 닉네임 같은 정보로는 연결하지 않는다.

### 11.3 근거리 음성

| 규칙        | 값                                                                   |
| ----------- | -------------------------------------------------------------------- |
| 거리        | 벽을 돌아가는 실제 경로의 칸 수(직선 거리 아님)                      |
| 들리는 범위 | 5칸 이하면 새로 들림. 이미 들리던 사람은 6칸까지 유지. 7칸 이상 끊김 |
| 음량        | 1 / (1 + 거리) × 0.7^모퉁이 수                                       |
| 먹먹함      | 저역 통과 20,000Hz × 0.65^모퉁이 수                                  |
| 좌우        | 내가 바라보는 방향 기준 방위각으로 스테레오 배치                     |
| 사용자 조절 | 전체 음량(기본 70%), 모든 소리 끄기, 친구별 목소리 끄기              |

### 11.4 효과음

| 소리                  | 들리는 거리 |
| --------------------- | ----------- |
| 발소리(이동 완료마다) | 4칸         |
| 감지기 발동           | 6칸         |
| 덫 발동               | 6칸         |

그 밖에 카운트다운·포획·탈출·승패 같은 자기 상태 안내음 13종과 장치 점검용 확인음이 있다.

### 11.5 권한과 개인정보 안내

- 카메라 동의에는 만 14세 이상 확인이 필요하다(6.2). 대기실의 개인정보 안내 상자에 안내 문장이 있다.
- 원본 영상은 게시하지 않고 가공된 흑백 얼굴만 게시한다.
- 미디어 연결 권한은 서버가 경기 단위로 발급하며 발급 후 5분이면 만료된다.

## 12. 종료·복구·재경기

### 12.1 경기가 끝나는 조건

- 승패(5.1) → `RESULT`
- 중단 → `ABORTED`(경기 무효)

| 중단 사유                | 언제                                                                               | 화면 문구                                                |
| ------------------------ | ---------------------------------------------------------------------------------- | -------------------------------------------------------- |
| `GAME_CONNECTION_LOST`   | 로딩·경기 중 참가자 한 명의 연결이 끊김(도망자·술래 모두)                          | `<이름>`님의 연결이 끊겨 경기가 무효 처리되었습니다.     |
| `SERVER_TICK_OVERLOAD`   | 서버 틱이 한 번 1초 넘게, 또는 10초 안에 세 번 250ms 넘게 밀리거나 틱 처리 중 예외 | 서버 지연으로 경기가 무효 처리되었습니다.                |
| `MEDIA_UNAVAILABLE`      | 미디어 연결 준비 실패, 연습·로딩·경기 중 미디어 실패                               | 미디어 연결을 사용할 수 없어 경기가 무효 처리되었습니다. |
| `MEDIA_POLICY_UNCERTAIN` | 미디어 수신 권한을 확정하지 못함                                                   | 미디어 권한을 확인하지 못해 경기가 무효 처리되었습니다.  |
| `DEMO_OPERATOR_ABORT`    | 데모 운영자가 라운드를 끝냄                                                        | 관리자가 라운드를 끝냈습니다.                            |
| (사유 없음)              | 미로 준비 30초 초과(미해결 미디어 없음), 인스턴스 무결성 실패                      | 경기를 계속할 수 없어 무효 처리되었습니다. …             |

`RESULT`에 도달한 경기는 그 뒤의 실패로 무효가 되지 않는다.

### 12.2 연결 끊김

- 서버는 2초마다 하트비트를 보낸다. 6초 동안 응답이 없으면 끊긴 것으로 본다.
- 브라우저도 6초 동안 하트비트를 못 받으면 연결 끊김 화면을 띄운다.

| 경우                   | 화면 제목                                                                     |
| ---------------------- | ----------------------------------------------------------------------------- |
| 방 만료(4001)          | 방의 대기 시간이 끝났습니다                                                   |
| 방장이 내보냄(4002)    | 방장이 대기방에서 내보냈습니다                                                |
| 시연 방장이 떠남(4003) | 시연이 종료되었습니다(2.5초 뒤 `/showcase`로)                                 |
| 그 밖                  | 게임 연결이 끊겼습니다. 방 코드가 있으면 그 코드로 다시 참가할 수 있다고 안내 |

### 12.3 재접속

- 일반·시연 방에서 경기(`PLAYING`) 중 연결이 끊기면 서버가 그 자리를 **25초** 비워 둔다. 끊긴 사람의 캐릭터는 그 자리에 멈추고(입력이 없으니 유지 이동도 곧 풀린다) 잡힐 수 있으며, 경기는 이어진다. 브라우저가 같은 연결로 자동 재접속하면 화면이 그대로 이어진다. 25초 안에 못 돌아오면 전처럼 `GAME_CONNECTION_LOST`로 무효다(S15P21C204-391).
- 끊긴 사람 화면에는 `연결이 끊겨 다시 연결하는 중입니다…`, 남은 사람 화면에는 `○○님의 연결이 끊겨 돌아오기를 기다립니다…`가 뜬다.
- 경기 중 페이지를 새로고침해도 25초 안이면 같은 자리로 돌아온다. 떠나는 순간 재접속 토큰을 그 탭의 저장소에 적어 두고 새 페이지가 그것으로 다시 붙는다. 탭을 닫아도 방을 떠난다고 알리지 않으므로 25초 동안 자리가 남는다(S15P21C204-396). 시연 방도 같다. 돌아온 페이지는 시연 규칙(맵 고정 표시, 나가면 `/showcase`)을 그대로 쓴다(S15P21C204-403).
- 그 밖의 단계(대기실·장치 점검은 자리 해제, 팀 연습~카운트다운은 대기실 복귀)는 전과 같다.
- 데모 방만 자리와 세션을 유지한다. 운영자가 새로고침하면 경기 중에도 다시 들어온다. 방이 비고 120초가 지나면 닫힌다.

### 12.4 재경기

| 방   | 선택지(방장만)                                                                                   |
| ---- | ------------------------------------------------------------------------------------------------ |
| 일반 | `같은 팀으로 재경기`, `역할 바꿔 재경기`, `로비로 돌아가기`(역할 새로 추첨)                      |
| 데모 | `도망자로 재경기`, `술래로 재경기`, `로비로 돌아가기`(관리자 역할 유지)                          |
| 시연 | `같은 자리로 다시 시작`, `로비로 돌아가기`. 역할 바꾸기는 없다(역할은 `/showcase`에서 고른 자리) |

재경기는 이전 경기의 미디어 정리가 끝나야 진행된다(그동안 `다음 경기를 위해 연결을 정리하고 있습니다.`). 모두 다시 준비한 뒤 시작한다.

### 12.5 방 만료

| 단계               | 만료                                                            |
| ------------------ | --------------------------------------------------------------- |
| `LOBBY`            | 무활동 `ROOM_IDLE_TTL_MS`(운영 설정 600초)                      |
| `DEVICE_CHECK`     | 단계 시작 300초 뒤. 사람이 있으면 미준비자만 내보내고 `LOBBY`로 |
| `RESULT`·`ABORTED` | 단계 시작 300초 뒤 방을 닫음                                    |
| 팀 연습 ~ 경기     | 만료 판정 안 함                                                 |
| 모든 단계          | 살아 있는 세션이 0이면 닫음                                     |

남은 시간이 60초 이하가 되면 `이 방은 N초 후 정리됩니다.`를 보여 준다. 방장이 나가면 연결 중인 사람 중 가장 먼저 들어온 사람이 방장이 된다(시연 방은 대기 중 방장이 나가면 방이 닫힌다).

근거: [server.md 9.3–9.6](impl/server.md#93-중단-사유), [web.md 5.5·11장](impl/web.md#55-연결-끊김), [game-core.md 11장](impl/game-core.md#11-연결-상실-중단-이벤트).

## 13. 기술·입장·운영 구조

### 13.1 구조

| 파트                 | 하는 일                                                                             |
| -------------------- | ----------------------------------------------------------------------------------- |
| `apps/web`           | React + three.js 화면, 입력, 카메라·얼굴 처리, LiveKit 클라이언트                   |
| `server`             | Colyseus Room, HTTP 입장, 권위 판정 구동, 미디어 권한 발급, 운영 명령과 관측        |
| `packages/protocol`  | 웹·서버가 함께 쓰는 메시지·상태 계약(제품 `0.2.0`, 진단 `0.1.0`)                    |
| `packages/game-core` | 서버 전용 순수 규칙(이동·포획·장비·교환·출구·승패·시야·배치). 웹은 import할 수 없다 |
| `infra`·`scripts`    | Jenkins, Docker compose, nginx, 배포·스모크·감시 스크립트                           |

제품 방 이름은 `kkakkung`이고 방 코드로 구분한다. 개발용 `sandbox` 방은 제품 서버에서는 등록되지 않는다.

### 13.2 입장과 접근 경계

| 입장 방식(서버 설정)                  | 방 만들기                            | 방 코드로 참가        | 초대 링크             |
| ------------------------------------- | ------------------------------------ | --------------------- | --------------------- |
| `gitlab-sso`(`SERVICE_AUDIENCE=team`) | 로그인한 누구나. 계정당 방 1개(기본) | 로그인한 누구나       | 가능                  |
| `guest`(`SERVICE_AUDIENCE=public`)    | 누구나. 접속 출처당 방 2개(기본)     | 불가                  | 방장 초대 링크로 참가 |
| `invitation`(기본)                    | 운영자 초대 링크가 있어야 함         | 초대 링크가 있어야 함 | 운영자가 발급         |

| 방 종류  | 경계                                                                                                                                   |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 데모     | `/demo`는 호스트 SSO 로그인 뒤 운영자 이메일 목록(`DEMO_ADMIN_EMAILS_FILE`)에 있어야 발급. 운영 API는 운영 토큰. `DEMO_ROOMS=1`일 때만 |
| 시연     | `/showcase`는 호스트 SSO 로그인 + 운영자 목록. `SHOWCASE_ROOMS`가 0이면 닫힘                                                           |
| 운영 API | 운영 토큰(Bearer). 공개 주소에서는 nginx가 `/api/operations`를 404로 막는다                                                            |

- 운영은 SSO 방식이다. 공개 범위는 lab.ssafy.com 로그인 계정 전체(SSAFY 교육생)이고, 데모·시연은 팀원과 등록 이메일(화이트리스트)만 들어온다. 게스트 방식은 쓰지 않기로 결정했다([결정 정정표](spec/decisions.md)).
- 한 SSO 계정이 다른 창에서 이미 방에 있으면 새 입장은 `ALREADY_IN_ROOM`이다.
- 세션은 첫 접속 60초(데모·시연 10분), 활동 30분, 최대 2시간이다.
- 호스트의 실제 SSO·운영자 목록 값은 저장소 밖이다.

### 13.3 상시 운영 한도

저장소의 제품 compose(`continuous`) 기준 값이다. 실제 서버의 `production.env`가 덮는 값은 저장소 밖이다.

| 설정                    | 값                                       | 뜻                                                                        |
| ----------------------- | ---------------------------------------- | ------------------------------------------------------------------------- |
| `MAX_ROOMS`             | 10                                       | 동시에 연습~경기 중인 일반 방 수                                          |
| `LOBBY_MAX_ROOMS`       | 30                                       | 동시에 열어 둘 수 있는 일반 방 수                                         |
| `SHOWCASE_ROOMS`        | 기본 1                                   | 동시 시연 방 수(별도 예산)                                                |
| `DEMO_MAX_ROOMS`        | 3                                        | 동시 데모 방 수(별도 예산)                                                |
| `MAX_ROOMS_PER_ACCOUNT` | 기본 1                                   | SSO 계정당 방 생성                                                        |
| `MAX_ROOMS_PER_ORIGIN`  | 2                                        | 게스트 접속 출처당 방 생성                                                |
| `ROOM_IDLE_TTL_MS`      | 600,000                                  | 대기실 무활동 만료                                                        |
| 입장 방식               | `team` / `gitlab-sso`                    | SSO 로그인 입장                                                           |
| 미디어                  | `livekit`                                | public 입장으로 바꾸려면 구독 방식이 `publisher-permissions`여야 기동된다 |
| 월 사용량 가드          | 남은 분이 예비 300분 이하면 새 경기 차단 | `LIVEKIT_MONTHLY_MINUTES`를 설정했을 때만                                 |

좌석 총량은 `max(LOBBY_MAX_ROOMS, MAX_ROOMS) × 6 + SHOWCASE_ROOMS × 4`다. 미디어가 구성되지 않은 제품 서버는 일반·시연 입장이 닫히고 데모 방만 열린다.

### 13.4 배포와 관측

- `develop` 머리가 바뀌면 Jenkins가 비밀 스캔 → 검증 → 이미지 빌드 → 배포를 한다.
- 배포 순서는 다음과 같다.
  1. 매니페스트 확인
  2. 공개 격리 검사
  3. drain
  4. 컨테이너 교체
  5. 준비 확인
  6. resume
  7. DP-06 Cloud 스모크(실제 6인 라운드)
  8. 공개 재검사
  9. last-good 기록
- 교체 뒤 실패하면 이전 이미지로 롤백을 시도한다. 롤백도 실패하면 `ROLLBACK_BLOCKED`로 남는다.
- 서버는 준비 상태(`/health/ready`)를 사유 코드와 함께 공개한다. 구조화 이벤트·metric·경보도 남기며, 경보는 critical만 웹훅으로 보낸다.
- 호스트 감시 잡이 30분마다 LiveKit 사용량을 조회해 알림을 보낸다. 5분마다 서비스 생존도 확인한다.

## 14. 검증 현황

**기본 검사 `pnpm verify`**는 다음 순서로 돈다. 각 단계는 앞 단계가 통과해야 실행된다.

1. 포맷
2. lint와 import 경계
3. 타입 검사
4. Vitest
5. 빌드
6. 제품 자산 검사
7. Playwright e2e(Chromium, 미디어 끈 로컬 서버)

**CI는 `pnpm verify`를 그대로 돌리지 않는다.** MR 빌드와 배포 빌드는 `ci-plan.mjs`의 모드별 계획만 실행한다.

- **MR:** 바뀐 경로에 따라 일부 단계를 뺀다. 자산이 안 바뀌면 자산 검사를, 웹 경로도 의존성 파일(`package.json` 등)도 안 바뀌면 e2e를, 렌더 경로가 안 바뀌면 렌더링 e2e를 뺀다. 문서만 바뀌면 포맷 검사와 계약 시험 두 단계만 돈다.
- **배포:** 타입 검사와 무거운 통합 시험 두 파일만 돈다.

**기본 실행에서 건너뛰는 시험**

## 15. 남은 결함과 과제

파트 문서가 코드로 확인한 결함을 영향이 큰 순서로 모았다. 사용자가 의도라고 결정한 동작과 이미 고친 결함은 [16장](#16-결정-사항)과 [결정 정정표](spec/decisions.md)로 옮겼다.

**따로 둔 것**

1. **Cloud 시험 케이스 8개(QA-02·03·04·05·06·09·11·12)는 BLOCKED 스텁 그대로 둔다.** 저장소만으로는 통과할 수 없는 관문이라 이번 개발 범위와 따로 다룬다(2026-09-25 결정). ([infra.md](impl/infra.md#17-확인된-한계와-코드-쪽-발견))

**참고 — 운영에서 쓰지 않는 경로**

- **게스트(`SERVICE_AUDIENCE=public`) 방식으로 배포하면 반드시 실패한다.** 운영은 SSO(`team`) 방식이고 게스트 방식은 쓰지 않기로 결정되어([결정 정정표](spec/decisions.md)) 현재 운영에는 영향이 없다. 게스트 공개를 다시 검토할 때 고쳐야 한다.
  - 공개 격리 검사는 public이면 `/api/config`가 200이길 요구한다.
  - 전진 배포는 운영 경로가 있으면 항상 DP-06 Cloud 스모크를 쓴다. DP-06 하네스는 같은 주소가 막혀 있길(301·302·401·403) 요구해 `DP06_ISOLATION`으로 실패한다.
  - 이어지는 롤백은 HTTP 스모크를 쓰는데, 이것도 SSO 302 리다이렉트를 요구해 실패한다. 결과는 `ROLLBACK_BLOCKED`다.
  - ([infra.md 7·9·17장](impl/infra.md#17-확인된-한계와-코드-쪽-발견), [release-sequence.mjs:312](../scripts/lib/release-sequence.mjs#L312), [release-sequence.mjs:473](../scripts/lib/release-sequence.mjs#L473), [DeploymentSmokeHarness.ts:360](../tests/cloud/DeploymentSmokeHarness.ts#L360))

## 16. 결정 사항

**결정된 것**(이유는 [결정 정정표](spec/decisions.md))

| 항목                                | 결정                                                                                                                                                                                                                                                                                                                                                                       |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 경기 중 미디어 발급 실패 한 건      | 라운드 전체를 무효로 한다(의도). 계속 진행하려면 규칙이 바뀌어야 해 비용이 크고, 누가 끊겨 무효가 됐는지는 화면이 알린다                                                                                                                                                                                                                                                   |
| 모션 모드의 키보드 이동             | 막는다(의도). 키보드는 카메라가 먹통이 된 뒤의 대체 수단이고, 키보드가 유리해 악용될 수 있어 전환 절차를 둔다                                                                                                                                                                                                                                                              |
| 서버 시야와 화면                    | 서버 시야를 3.5칸으로 줄여 화면과 맞추고, 안개가 시야 끝에서 닫히게 했다(S15P21C204-377)                                                                                                                                                                                                                                                                                   |
| LiveKit 사용량                      | 무료 계정을 계속 모니터링한다. 사용량·API 한도와 관련된 부분(계량기, 사용량 감시, API 한도·429 경보)은 모두 완료로 보고 더 바꾸지 않는다(2026-09-25)                                                                                                                                                                                                                       |
| 시연 방 맵                          | 방송한 소형 맵(15×15)으로 경기하게 고쳤다(S15P21C204-376)                                                                                                                                                                                                                                                                                                                  |
| 관전자 미디어 복구                  | 관전 중인 종료 도망자도 교체 권한을 받는다. 관전자의 준비 실패는 라운드를 무효로 만들지 않는다(S15P21C204-380)                                                                                                                                                                                                                                                             |
| 결과 문구·교환 알림·적 별칭         | 결과 문구는 실제 탈출·포획 수를 쓰고(사유 코드 이름은 유지), 새 정보 없는 교환 수락도 두 사람에게 종료를 알리며, 적 별칭은 경기 인스턴스를 회수할 때만 지운다(S15P21C204-380)                                                                                                                                                                                              |

| 시연 방 자리·재시작                 | 자리마다 시작 위치·출구를 고정하고, 결과 뒤 같은 자리로 다시 시작할 수 있다. 역할 바꾸기는 없고 제한시간은 일반 방과 같다(S15P21C204-390)                                                                                                                                                                                                                                  |

| 덫 구속과 술래 경보                 | 덫 구속은 3초다. 덫·감지기가 발동하면 모든 술래가 거리와 상관없이 경보음·플래시·위쪽 알림을 받는다(S15P21C204-386)                                                                                                                                                                                                                                                         |

| 탈출 완료 신뢰 경계                 | 지금처럼 둔다. 자세 판정은 카메라 영상이 브라우저를 떠나지 않으므로 브라우저가 하는 입력이고, 서버는 그 결과를 도전 상태·시각·위치로 확인해 받는다                                                                                                                                                                                                                         |
