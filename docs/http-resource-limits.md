# 운영·미디어 HTTP 자원 상한

관련 Jira: [S15P21C204-204](https://ssafy.atlassian.net/browse/S15P21C204-204).
K01/W04/W14의 요청 입구·동시 작업 제한이다. 감사 파일의 장기 보관·축약은 K02에 남는다.
운영 도메인의 팀원 SSO와 LiveKit API 예산은 유지한다.

## 적용 경계

제품 서버는 JSON 파싱 전에 `/api/operations/*`, `/api/media/grants`, `/api/media/report`를
분류한다. Express와 일치하게 대소문자와 마지막 슬래시를 처리한다. 잘못된 JSON·운영 인증도
같은 제한을 통과해야 하며 허용된 요청만 감사·미디어 처리기에 도달한다.

| 종류               | 키                           | 이동 1초 내 키별 / 전체 | 동시 HTTP / 미완료 처리기 |
| ------------------ | ---------------------------- | ----------------------- | ------------------------- |
| 무인증·잘못된 인증 | 신뢰 프록시 정책을 적용한 IP | 5 / 20                  | 4 / 4                     |
| 정상 운영 인증     | 서버의 운영 그룹             | 60 / 120                | 16 / 16                   |
| 정상 미디어 세션   | 검증된 내부 세션 ID          | 12 / 240                | 128 / 128                 |

각 그룹은 별도 용량을 사용한다. 키 저장은 차원별 최대 4,096개이며 거절된 요청은 타임스탬프를
계속 추가하거나 냉각 기한을 연장하지 않는다. 운영 토큰·세션 토큰·임의 Bearer 원문은 보관하지 않는다.
이 수치는 로컬 혼합 HTTP 회귀의 초기 상한이며 실제 10방 Cloud 부하의 인수 값이 아니다.

HTTP 연결이 종료돼도 내부 비동기 감사/미디어 작업이 진행 중이면 작업 용량은 유지한다.
처리기의 Promise가 종결될 때만 반환하므로 연결 중단으로 대기열 상한을 우회하지 못한다.
본문 파싱 전 거절과 작업 상한 초과는 `429/RATE_LIMITED`다.

## 본문과 관측

기존 API·매치메이킹의 2,048바이트 상한과 Origin 검사를 유지한다. 헤더를 받은 뒤 본문 완료까지
5초를 넘으면 `408/BODY_TIMEOUT`으로 연결을 닫고 버퍼·타이머를 정리한다. 본문 중 연결 중단과
오류도 같은 자원을 반환한다. 서명 검증용 LiveKit webhook의 raw body에는 이 사전 파싱을 적용하지 않는다.
OPTIONS는 Bearer가 없고 감사/미디어 작업을 수행하지 않아 새 빈도 제한에서 제외하며 Origin 검사는 유지한다.

제품 샘플러는 `http.requests.active`, `http.requests.work`, `http.requests.rejected`를
각각 현재 연결 수·미완료 처리기 수·프로세스 누적 거절 수로 기록한다. 사용자 ID나 요청 본문은 포함하지 않는다.
헤더 전송 전 소켓, 프록시·네트워크 전체 용량, webhook과 영구 감사 기록의 장기 보관은 별도 경계다.

## 검증 범위

`server/test/session/product-http-limits.test.ts`는 실제 HTTP 서버에서 잘못된 JSON 폭주,
인증별 격리, 60개 합성 세션, OPTIONS, 느린 chunked 본문, 연결 중단 후 미완료 작업,
서명 raw body 경계를 검사한다. 실제 제품 조립에서는 운영 초대 발급·6개 Colyseus 로비 연결과
tick 진행·관측 지표를 과다 운영 요청과 함께 확인한다. 코어·Cloud는 테스트 경계이며 실제 게임
6대 완주, 장기 감사 파일 증가, 원격 drain 지연과 60세션 Cloud 성능을 통과했다고 해석하지 않는다.
