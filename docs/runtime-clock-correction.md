# 운영 확인의 미세 시각 보정

관련 Jira는 [S15P21C204-216](https://ssafy.atlassian.net/browse/S15P21C204-216)이다.
215의 로컬 전체 제품 통합에서 시스템 시각이2ms, 후속 시험에서5ms 역행하며 기존
RuntimeEvidence가 CLOCK_ROLLBACK으로 영구 잠그는 현상을 관측했다. 이 조건에서 진행 중인
경기는 MEDIA_POLICY_UNCERTAIN으로 중단됐다. 별도의 continuous 입장503 사례는 원인을
확정하지 않았으며 이 변경으로 해결됐다고 계산하지 않는다.

RuntimeEvidence는 마지막으로 수락한 최대 epoch 시각보다5ms까지 뒤인 표본을 허용한다.
이때 비교 기준을 낮추지 않고 기존 최대 시각을 사용한다. 예를 들어20→18→16→15는
기준20을 유지하지만 다음14는6ms 역행이므로 잠근다. 직전 원시 표본과만 비교해 작은
역행을 계속 누적하는 동작은 허용하지 않는다.5ms는 이번 운영 정책의 고정 허용 폭이며
Cloud 시계 오차나 토큰 회수 buffer의 검증값을 대체하지 않는다.

원본 자료의 만료/신선도 시각, 파일 재확인의5초 단조시간 lease, 공식 예산·프로젝트·파일
대조는 유지한다. 만료나 큰 역행으로 이미 잠긴 자료는 이후 작은 시각 변화나 새 조회로
복구하지 않는다. 토큰 만료·초대 수명·경기 시각·사용량 예약 값은 변경하지 않는다.

진단의 clockCorrectionCount는 허용된 역행 표본의 수이며 독립적인 OS 보정 이벤트 수가 아니다.
maxClockCorrectionMs는 그 표본의 최대 역행량, clockRollbackMs는 잠금을 발생시킨 역행량이다.
이 진단에는 토큰·신원·운영 파일 원문이 포함되지 않는다.

검증은 관측된2ms와 경계5ms, 단일/누적6ms, 실제 만료·stale·파일 변경·단조 lease,
continuous 정책을 포함한다. 구 구현은 새 보정 회귀3개에서 실패했고 수정 후 해당 파일41개를
통과했다. 선행215의c83102b를 포함한 pnpm verify259파일2,697개·22 E2E(1.0분),
포맷/계약33·도구11/lint/타입/빌드/실제 Worker·자산 PASS다. 원격 CI·MR·배포는 확인 뒤 기록한다.
팀 SSO와 공개 설정 차단을 유지하며 이 수정은 G1·실제6대·10방 인수를 대신하지 않는다.
