캐시는 권한 원본이 아니다. 만료 뒤 중복 요청이 도착해도 현재 세대·경기·연결·토큰 수명을 다시 검증한다. 회수 요청 캐시가 가득 찼을 때 원격 회수를 막지 않으며 세대별 진행 중 작업은 별도로 합친다. 위 10분은 내부 기록 정리 시간이며 배포 유효시간이나 수동 운영 증거 갱신 기한이 아니다.

`releaseMatch`는 내부 `MediaCoordinatorRuntime` 확장이며 브라우저 wire와 기본 EXEC-CONTRACT-3 계약을 늘리지 않는다. 제품 Room의 `onDispose`와 `startNewRound`에서 호출한다. 인증된 게임 연결이 연 scope만 받으므로, 끝난 경기의 늦은 프레임은 새 권한을 만들지 않는다. 다른 살아 있는 경기의 세대와 기록을 정리하지 않는다.

정책 폐기 시 먼저 AbortSignal과 terminal 상태를 고정하고 lookup을 제거한다. 늦은 구독 응답/트랙 조회는 이미 닫힌 객체를 참조하므로 새 권한을 확인한 것으로 계산하지 않는다. Generation 자체는 로컬 시야와 독립적으로 원격 회수/예약 반환이 끝날 때까지 유지한다.

현재 continuous 방식에서 반환 완료된 일반 세대는 자동 정리된다. attested 방식의 공식 정산 대기 예약과 공유 회수 checkpoint가 참조하는 세대는 이 정리로 제거하지 않는다. `SharedRetryCheckpoint.write`는 여러 회수 엔진의 합집합을 보존하므로 단순 배열 누락으로 압축할 수 없다. 기존 24시간 증거 보관 정책에 맞는 공동 checkpoint·저널·장부 압축과 복원 검증은 W14/W19에서 수행해야 한다.

로컬 회귀는 10,000회 요청과 합성 경기의 상한/정리, Coordinator의 연속 경기·정산 대기 보존, 정상 tick·방 폐기·재경기, 기존 세대/권한/회수 오류 경로를 검사한다. 실제 Cloud 원격 회수, 운영 프로세스의 장시간 RSS 추세, 10방 용량 증거로 대체하지 않는다. `inspectRetention()`은 내부 집계 수만 반환하며 토큰·identity·플레이어 위치를 노출하지 않는다.
