# 시설 렌더링과 검수

2026-09-13 · [S15P21C204-189](https://ssafy.atlassian.net/browse/S15P21C204-189) · [MVP 실행계획 W16/V0–V5](mvp-completion-plan.md)

## 표현 기준

좁은 시설 복도, 얼룩진 회색 벽과 청록 하단 패널, 어두운 천장, 작은 따뜻한 등기구를 사용한다. 시선 방향의 근거리 조명으로 벽과 얼굴을 읽을 수 있게 하고 1.85–3셀 안개로 먼 가시 경계를 정리한다. 강한 점멸·카메라 흔들림·그림자 맵·후처리는 추가하지 않았다. 실제 공포감과 길 찾기는 신규 참가자 평가로 판정한다.

벽 높이 1.2셀, 카메라 높이 0.8셀, 큰 머리 0.48셀, 가로 FOV 80도와 기존 서버 좌표/이동 시간을 유지한다. 벽 면·출구·벽 장비는 동일한 `wallModel` 방향을 사용한다. 장비 색에만 의존하지 않도록 벽 감지기와 바닥 덫의 형상을 구분하고 무장 상태는 표시등·덫의 돌출 형태로 표현한다.

상대 몸·머리·얼굴은 하나의 group에서 서버 action을 보간한다. 미래 위치를 예측하거나 맵 정보를 보충하지 않는다. `visibilityMask`를 몸과 얼굴에 공통 적용하며 수신하지 않은 상대 역할을 색으로 추정하지 않는다. 얼굴 영상이 없는 검수 장면은 회색 판이며 실제 사용자 얼굴이 아니다.

일반 품질은 DPR 1.5, 가벼운 품질은 DPR 1이다. 가벼운 품질에서는 보조 점광원만 제거하고 벽·출구·장비·얼굴·시야 정보는 같다. 시설 텍스처 두 개는 128×128 RGBA이며 코드에서 만든다. 지오메트리·재질은 장면 안에서 공유하고 해제한다. 원격 얼굴 텍스처는 기존 `FaceTextures`가 관리하며 아바타가 대신 폐기하지 않는다.

## 검수 방법

루트에서 `pnpm dev:web`를 실행한 뒤 개발 `/preview`의 **렌더 검수**를 연다. 진단용 합성 개인 뷰만 사용하며 방·좌석·카메라·미디어 연결을 만들지 않는다. 운영 빌드에는 개발 PreviewApp 진입점이 포함되지 않는다.

1. 복도·코너·출구/장비·상대 5명을 북/동/남/서에서 확인한다. 벽 뒷면 노출, 출구/장비 방향과 가독성, 상대 몸/얼굴 정렬을 본다.
2. 이동 시점 0–20을 바꾸어 상대의 시작·중간·도착 위치를 확인한다.
3. 기본/가볍게 전환 후 같은 정보가 보이는지 확인한다.
4. 장면 교체 후 geometry/texture 수가 같은 장면의 기준으로 돌아오고, 렌더 해제/재진입 후 그 기준 이하인지 확인한다. 새 Canvas는 앞선 장면의 아바타 자원을 아직 GPU에 올리지 않아 더 적을 수 있다. FPS·프레임 p95는 해당 브라우저의 약 1초 표본이며 실제 제품 부하 합격치가 아니다.
5. 경기 HUD의 역할·승리 조건·남은 시간·인원·구속/도전 상태와 사이드바의 내 카메라·지도·장비를 함께 확인한다.

자동 검사는 `pnpm exec vitest run apps/web/src/features/game/scene apps/web/src/features/game/flow/game-hud.test.ts`, 브라우저 검사는 `pnpm exec playwright test tests/e2e/facility-rendering.spec.ts`다. 브라우저 검사는 로컬 서버를 자체 실행한다. 실제 제품 렌더러를 쓰되 전체 경기 완료 시험으로 계산하지 않는다.

## 실제 인수에서 남은 조건

- 실제 6대에서 비전 추론·가공 얼굴 5개·음성·맵을 동시에 사용한 FPS/프레임 p95, 장시간 메모리 및 장치별 최소 품질 확인.
- 실제 얼굴 영상 가독성, 이동/회전 지연, 자신의 카메라 상태·게임 정보가 장면을 가리지 않는지 확인.
- 코너/포획/출구 순간의 긴장감과 길 찾기·장비 식별, 신규 참가자의 규칙 이해 및 불편 평가.
- 위 실제 결과를 source SHA·브라우저/장치·품질·실행 시각과 함께 W18 기록에 연결한다. 합성 장면이나 자동 검사 통과만으로 V5 전체 인수 또는 MVP 완료를 선언하지 않는다.
