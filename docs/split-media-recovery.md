## 기록과 소유 경계

기존 JournalRecord의 기본 방/신원은 개인 MIC 게시·수신 원본이다.
선택 필드 `splitOwnership`은 CAMERA 원본의 방/신원과 가능한 다른 개인 수신 방을 담는다.
두 토큰을 서명하기 전에 모든 목적지를 확정해 같은 PREPARED 기록에 저장해야 한다.
현재 세대 할당·grant 발급 생산자는 이 필드를 생성하지 않는다.

- 최대 다른 수신 방5개로 원본2개·전달 대상10개·방7개를 소유한다.
- 방들은 같은 namespace/서버 epoch에 속해야 한다. 중복·자기 방·다른 epoch·다른 namespace·
  같은 신원·필드 누락·과도한 목적지·토큰 등 알 수 없는 필드는 거절한다.
- token·비밀키·플레이어의 개인정보를 저장하지 않는다. 목적지 목록은 실제 전달 여부와 별개다.
  미입장, API timeout 또는 전송 ACK 유실도 정리 대상에서 빼지 않는다.
- 한 세대의 기록을 진행하면서 목록을 추가·삭제·교체할 수 없다. append와 재생에서 검사하고,
  readiness 및 복구 대조에도 같은 소유 목록을 요구한다. 중첩 배열은 기록 전에 복사한다.

## 실행 중 회수와 재기동 복구

실행 중 RevocationRetryBindings와 재기동 RecoveryCleanupBindings가 같은 소유 목록을 사용한다.
원본 두 개를 먼저 회수하고 모든 가능한 전달 신원에도 회수 ACK와 실제 부재를 요구한다.
토큰 만료나 글로벌 방 목록에서 보이지 않는 것만으로 회수를 성공 처리하지 않는다.
회수 API의404는 성공 ACK를 대체하지 않는다.

모든 대상이 확인된 뒤에만 묶음의 REVOKED를 내구 기록하고 세대 종료/예약 정산으로 진행한다.
하나라도 실패하면 묶음을 미확인으로 유지하며 관련 방을 먼저 삭제하지 않는다.
재시도 intent도 묶음 하나를 소유하고 공유 API 예산·취소·전송 직전 가드를 유지한다.
복구 sweep은 보조 방과 모든 목적지 방도 개별 확인한다.

이미 REVOKED인 묶음에서 여러 참가자가 다시 나타나면 각각 미확인 관측에 보존한다.
이전 REVOKED를 되돌리거나 다른 참가자의 관측을 덮어쓰지 않는다.
방 부재 재사용은 묶음 전체의 내구 회수·정산·원본/갱신 토큰 유효기간을 확인해야 한다.
축약 콜백에 전달하는 기록도 중첩까지 보호해 목록을 변조할 수 없게 했다.

## 호환성과 배포 순서

기존 단일 연결 JSON과 checksum은 그대로 읽으며 새 필드는 기존 writer가 만들지 않는다.
이 reader/회수 지원을 먼저 검증·배포한 다음 공개 세대 할당·예약·서명·전달 생산자를 연결한다.
새 필드를 기록한 뒤의 롤백 후보도 이 reader를 포함해야 한다. 구 reader는 알 수 없는 필드를
거절하므로 새 기록을 구 형식으로 지우거나 축소해 롤백하지 않는다.

운영은 팀 SSO/기존 미디어 모드다. public+livekit 부팅 제한을 제거하지 않는다.
설정 parser·공개 capability·서버 권위 전달·수신 방 SID 대조·보수적 사용량 예약·
실제 제품 Cloud 인수는 다음 단계다. 이 코드는 공개 발급이나 전체215 완료가 아니다.
