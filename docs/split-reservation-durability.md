# 분리 미디어 발급 전 예약의 내구 경계

관련 Jira는 [S15P21C204-215](https://ssafy.atlassian.net/browse/S15P21C204-215)다.
[전달 요청 내구 기록](split-forward-durability.md)에 이어 예약 일부 성공과 서명 전 종료를
실제 기록으로 구분한다. 운영 팀원 제한과 공개 미디어 설정 차단은 유지한다.

## 처리 순서

기존 세대 저널의 reservationIntent에 고정 예약 루트와 최초6슬롯 블록들의 요청을 저장한다.
RESERVING 기록을 fsync한 뒤 실제 UsageBudget을 예약한다. 모든 블록이 계획과 일치하고
ACTIVE인 것을 확인한 COMMITTED 기록이 fsync된 뒤에만 토큰을 서명한다.
별도 체크포인트나 앱별 저장소를 추가하지 않는다.

서버가 중간에 종료되면 준비 기록과 실제 사용량 파일을 대조한다. 부분 예약을 없는 것으로
취급하지 않으며, 존재하는 예약은 원래 소유 범위의 실제 원격 회수·부재 확인과 기존 정산
경로를 따른다. 임의의 예약이나 원격 성공 기록을 만들어 복구하지 않는다.

예약 전 단계에서 종료됐고 해당 루트와 모든 자식 예약이 없다는 것이 입증되면 ABORTED로
기록한다. 이 상태는 토큰 서명 전 중단이며 원격 회수 완료인 REVOKED와 다르다.
reader는 RESERVING·종료 시각·미종결 전달0·실제 예약0을 다시 검사한다.
숫자가 아닌 예상외 접미자의 예약도 존재하면 빈 예약으로 인정하지 않는다.

배포의 failed-startup-recovery 소비자도 같은 서버 검증 함수를 사용한다. ABORTED는
abortedIssuances로 별도 집계하고 회수한 identities에 더하지 않는다. 종료 상태를
다시 열거나 다른 종료 상태로 바꾸는 기록은 거절한다.

## 호환성과 남은 범위

선택 필드가 없는 기존 단일/분리 기록을 읽되 이미 존재하는 세대에 새 발급 전 주장을
나중에 덧붙일 수 없다. 새 필드와 ABORTED를 모르는 구 reader로 저장소를 바로 되돌리는
것은 지원하지 않는다. 현재 운영은 새 split writer를 활성화하지 않으므로 reader를 먼저
배포하고 실제 인수 뒤 쓰기를 활성화한다.

이번 발급 준비 writer는 분리 모드에 연결한다. 기존 단일 모드는 공유 방 lease를 사용하므로
첫 예약 저장과 최초 journal 사이의 종료 간극은 별도 후속으로 남는다. 기존 단일 모드의
정상 회귀 통과를 해당 종료 간극의 해결로 해석하지 않는다.

## 검증 상태

실제 프로세스 종료·부분 예약·부정 기록·축약 회귀 10개를 포함한 관련 20파일 365개,
서버/QA 타입·변경 lint/포맷을 통과했다. 배포 복구 소비자는 40개이며 예약 계획의 역행,
뒤늦은 준비 주장, 계획 변경과 빈 ABORTED의 원격 회수 오집계를 거절한다.

최종 `pnpm verify`는 262파일 2,748개·브라우저 22개(1.1분), 포맷·계약 33개·도구 11개,
lint·타입·빌드·제품 자산을 통과했다. 전송 내구 수정과 같은 MR로 통합하고 정확한 통합
소스의 원격 CI·병합·배포를 별도로 확인한다. 실제 Cloud 및 전체 제품 인수는 미완료다.
