# 교체 가능한 호러 아바타 에셋 설계

## 목적

`S15P21C204-323`에서 코드로 기본 도형을 조립한 임시 캐릭터를 실제 로컬 3D 에셋 기반
아바타로 교체한다. 1차 목표는 사용자가 승인한 각진 로우폴리 호러 스타일이다. 도망자는
아이보리 후드와 긴 로브 안에 가공된 실시간 얼굴이 보이고, 술래는 굽은 몸·긴 팔과 손가락·
천으로 감싼 머리·드러난 입과 이빨로 세 칸 거리에서도 역할을 구분할 수 있어야 한다.

경기 규칙, 서버 이동, 수신자별 시야, 얼굴 송수신 정책은 바꾸지 않는다. 이후 사실적 호러
모델을 제작할 시간이 생기면 게임 로직을 다시 고치지 않고 에셋 등록만으로 교체할 수 있는
구조를 만든다.

## 현재 상태와 문제

현재 미커밋 구현은 `FaceAvatar.tsx`에서 `BoxGeometry`, `SphereGeometry`,
`CylinderGeometry`, `ConeGeometry` 등을 조립한다. 이 방식은 역할별 키와 실루엣을 빠르게
시험할 수 있지만 사용자 콘셉트 이미지의 옷 형태, 천 표면, 손과 관절, 얼굴 구조를 표현하지
못한다. 실제 캡처에서는 술래의 입과 이빨이 머리 안에 묻혀 보이지 않았다. 콘셉트 PNG는
런타임 에셋이나 텍스처로 연결되지 않았으며, 한 장의 이미지를 캐릭터에 붙이는 방식은 회전
시 평면처럼 보여 채택하지 않는다.

현재 기본 도형 구현은 최종 결과로 커밋하지 않는다. 설계가 승인되면 필요한 테스트 의도만
보존하고 실제 모델 로더와 에셋으로 대체한다.

## 검토한 접근

### 1. 기본 도형을 계속 다듬기

의존성과 로딩 처리가 단순하지만 옷의 찢어진 가장자리, 비대칭 자세, 자연스러운 관절과
향후 사실적 모델 교체를 감당하기 어렵다. 빠른 프로토타입 외에는 사용하지 않는다.

### 2. 역할별 GLB와 공통 런타임 계약 사용 — 선택

도망자와 술래를 독립 GLB로 두고 노드, 재질, 애니메이션 이름을 공통 계약으로 고정한다.
현재 저장소에는 Blender가 없으므로 1차 로우폴리 원본은 저장소의 결정적 에셋 빌더가 사용자
콘셉트를 참고해 전용 메시·뼈대·애니메이션을 생성한다. 브라우저는 생성된 GLB만 읽으며 빌드
시마다 모델을 만들지 않는다. 향후 Blender 또는 전문 제작 모델도 같은 계약을 지키면 GLB
파일 교체로 연결할 수 있다.

### 3. 처음부터 사실적 모델 제작

오른쪽 참고 이미지 수준은 고밀도 조형, PBR 재질, 리토폴로지, LOD와 조명 조정이 함께
필요하다. 현재 웹 게임의 1차 캐릭터 교체 범위를 넘어선다. 1차 구조가 안정된 뒤 별도 에셋
작업으로 진행한다.

## 에셋 계약

에셋은 다음 공개 경로에 둔다.

- `apps/web/public/models/avatars/v1/runner.glb`
- `apps/web/public/models/avatars/v1/tagger.glb`
- `apps/web/public/models/avatars/v1/manifest.json`

각 GLB는 다음 이름을 제공한다.

| 이름           | 종류             | 용도                                             |
| -------------- | ---------------- | ------------------------------------------------ |
| `AvatarRoot`   | 최상위 노드      | 서버 보간 위치·방향과 역할별 스케일 적용         |
| `Rig`          | 공통 골격        | 현재 걷기 진행도와 애니메이션을 연결             |
| `FaceSocket`   | 도망자 전용 노드 | 실시간 얼굴 평면의 위치·회전·크기 기준           |
| `BodyMaterial` | 재질             | 역할별 천과 몸의 기본 표면                       |
| `idle`         | 애니메이션 클립  | 정지 상태의 미세한 호흡과 술래의 굽은 자세       |
| `walk`         | 애니메이션 클립  | 한 서버 이동 구간에 정규화된 반복 없는 걷기 동작 |

도망자와 술래는 같은 골격 이름을 사용하되 신체 비율과 메시가 다르다. 도망자는 `FaceSocket`을
반드시 제공하고 술래는 제공하지 않는다. `manifest.json`은 역할별 URL, 버전, 모델 크기, 삼각형
수, 재질 수, 애니메이션 이름, 얼굴 소켓 유무와 SHA256을 기록한다. 런타임은 파일 내부를 추측하지
않고 이 계약을 검증한 뒤 사용한다.

콘셉트 이미지는 시각 참고 자료이며 제품 텍스처로 포함하지 않는다. 새로 제작한 GLB와
텍스처의 생성 방식·파일 크기·해시·사용 목적은 `docs/third-party-assets.md`의 제품 자산 기록에
남긴다. 권리를 확인하지 않은 외부 모델이나 텍스처는 사용하지 않는다.

## 1차 로우폴리 시각 규격

### 도망자

- 술래보다 최소 25% 작고 폭이 좁은 실루엣
- 아이보리 후드, 어깨 망토, 발목까지 내려오는 각진 로브
- 얼굴을 덮지 않는 어두운 타원형 개구부와 별도 `FaceSocket`
- 로브 밑단과 소매는 좌우가 완전히 대칭이 아닌 찢어진 다각형
- 실시간 얼굴이 없을 때는 눈구멍이 있는 천 인형 형태의 비식별 대체 얼굴 사용

### 술래

- 도망자보다 최소 25% 크고 앞으로 굽은 실루엣
- 무릎 아래까지 내려오는 팔, 분리되어 읽히는 세 손가락, 긴 정강이
- 천으로 감싼 얼굴 전면에 검은 입과 두 줄의 밝은 이빨
- 등과 어깨를 덮는 어둡고 찢어진 천, 피부와 천 사이의 명도 차
- 정면·측면·후면에서 도망자 후드와 혼동되지 않는 머리와 어깨 형태

낮음과 중간 품질은 같은 로우폴리 메시를 사용한다. 낮음은 512px 색상 아틀라스와 단순 거칠기,
중간은 최대 1024px 색상·거칠기 아틀라스를 사용한다. 1차에는 별도 normal 맵과 후처리를
추가하지 않는다. 최대 여섯 명이 보여도 아바타 전체 삼각형 수 60,000, 역할별 재질 네 개,
아바타당 draw call 여덟 개를 넘지 않는 것을 목표로 한다.

## 런타임 구조

`FaceAvatars`는 계속 수신자별 `PrivateView`와 `visibilityMask`가 공개한 참가자만 그린다.
서버 좌표와 `sampleActor`의 위치·방향·보간 진행도도 유지한다. 새 구조는 표현 계층만 다음처럼
나눈다.

1. `avatar-manifest.ts`가 역할과 품질에 맞는 에셋 설명을 반환한다.
2. `avatar-loader.ts`가 Three.js `GLTFLoader`로 GLB를 한 번 로드하고 캐시한다. 새 런타임
   의존성은 추가하지 않고 현재 설치된 `three`의 addon을 사용한다.
3. `RoleAvatar.tsx`가 플레이어마다 장면과 재질을 복제한다. 골격·애니메이션 상태와 실시간 얼굴
   재질은 참가자 사이에 공유하지 않는다.
4. `AvatarAnimation.ts`가 `sampleActor`의 stride와 서버 행동 길이를 `idle`·`walk` 클립 시간으로
   변환한다. 위치와 방향은 애니메이션 root motion이 아니라 서버 보간만 결정한다.
5. `RunnerFaceSurface.tsx`가 `FaceSocket`에 기존 `FaceTextures` 또는 데모 stand-in을 붙인다.
   얼굴 텍스처 소유권과 정리는 계속 기존 `FaceTextures`가 담당한다.

모델 로딩 실패, 계약 불일치 또는 WebGL 자원 생성 실패 시 중립 기본 실루엣을 표시하고 경기를
중단하지 않는다. 오류에는 역할과 자산 버전만 남기고 참가자 ID나 얼굴 정보를 기록하지 않는다.
GLB는 경기 진입 전 웹 로딩 단계에서 미리 요청하지만 서버의 `GAME_LOADING` 준비 계약에 새
장벽을 추가하지 않는다.

## 향후 사실적 모델 교체

현재 품질 설정에 존재하지 않는 `high` 옵션을 이번 작업에서 UI에 추가하지 않는다. 향후 사실적
모델이 준비되면 manifest의 별도 변형으로 등록하고 같은 골격·클립·`FaceSocket` 계약을 유지한다.
골격 비율이 달라 애니메이션을 공유할 수 없으면 GLB 내부 클립만 교체하되 런타임 이름은 그대로
둔다.

사실적 모델은 단순 교체 파일이 아니다. 고해상도 PBR 텍스처, LOD, 더 엄격한 GPU 예산,
백룸 조명 조정과 대표 장치 측정이 별도 완료 조건이다. 로우폴리 모델은 삭제하지 않고 낮음·
중간 품질 및 복구용 에셋으로 유지한다.

## 검증

- 에셋 빌더가 같은 입력에서 동일한 SHA256의 GLB와 manifest를 생성하는지 검사한다.
- manifest와 실제 GLB의 필수 노드, 클립, 얼굴 소켓, 삼각형·재질 예산을 자동 검사한다.
- 역할별 크기, 팔 길이, 굽은 자세, 얼굴 소켓 유무를 순수 계약 테스트로 고정한다.
- 한 장면의 여러 참가자가 골격·애니메이션·얼굴 재질을 서로 공유하지 않는지 검사한다.
- GLB 로딩 실패와 계약 불일치에서 중립 실루엣으로 복구하고 자원을 한 번만 해제하는지 검사한다.
- 기존 행동 보간, 가시성, 역할 색, 실시간 얼굴 수명 테스트를 유지한다.
- `/preview` 렌더 검수에서 도망자 단독, 술래 단독, 정면 혼합 5명, 측면 혼합 5명 스크린샷을
  남긴다. 술래의 입·이빨·손가락과 도망자의 후드·얼굴 개구부가 실제 픽셀에서 보여야 한다.
- 낮음·중간 품질의 장면 재진입과 역할 교체를 반복해 geometry, texture, program 수가 누적되지
  않는지 검사한다.
- 서버 연동 E2E에서 두 브라우저의 이동·퇴장과 팀방 시작을 유지한다.
- 최종적으로 루트 `pnpm verify`와 제품 자산 검사를 실행한다. 실제 6대 장치·Cloud·사용성 인수는
  이 로컬 검증으로 대체하지 않는다.

## 변경 경계와 전달

주 변경은 `apps/web`의 렌더링, `apps/web/public/models/avatars/v1`, 결정적 에셋 빌더,
자산 문서와 관련 테스트다. `packages/protocol`, `packages/game-core`, `server`의 계약은 바꾸지
않는다. 현재 브랜치 `feat/S15P21C204-323-low-poly-horror-avatars`와 Jira
`S15P21C204-323`을 유지한다.

1차 완료는 로우폴리 GLB 두 개, `idle`·`walk`, 도망자 실시간 얼굴, 품질별 로딩, 실패 복구,
자동 검사와 실제 캡처 검수를 모두 통과한 상태다. 사실적 모델 제작과 `high` 품질 UI는 후속
범위이며 1차 완료로 보고하지 않는다.
