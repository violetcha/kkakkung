# 백룸형 미로 UI 개편 설계

## 목적

경기 화면의 마인크래프트형 블록 표현을 낡은 백룸형 1인용 미로로 교체한다. 서버가
권위적으로 관리하는 이동, 충돌, 가시 범위, 장비, 지도 교환 규칙은 바꾸지 않고 웹의 렌더링과
오버레이만 변경한다. 관련 Jira는 `S15P21C204-279`다.

## 시각 방향

- 통로는 논리 맵의 한 셀 폭을 그대로 사용하고 벽과 천장을 높여 한 사람이 겨우 지나가는
  좁은 복도로 보이게 한다.
- 사용자가 제공한 `ALBEDO.PNG`, `ROUGHNESS.PNG`, `NORMAL.PNG`, `SEAMLESSTEXTURE.PNG`를
  백룸 벽지 재질로 사용한다.
- 중간 품질은 albedo, roughness, normal 맵을 함께 쓰고, 저품질은 seamless 색상 맵만 사용해
  GPU 메모리와 셰이더 비용을 줄인다.
- 바닥은 얼룩진 무광 카펫, 천장은 누렇게 바랜 흡음 타일, 조명은 일정 간격의 형광등으로
  구성한다. 별도 후처리나 새 런타임 의존성은 추가하지 않는다.
- 기존 블록 테마는 비교와 복구를 위한 선택지로 유지하되 백룸형 테마를 기본값으로 삼는다.

## 렌더링 구조

`WorldCanvas`의 서버 뷰 입력과 `VisibleTerrain`의 가시성 필터는 유지한다. 백룸형 테마는
`ScenePrimitives`가 받은 공개 셀과 벽 면만 그리므로 보이지 않는 지도 정보가 브라우저에
추가되지 않는다.

백룸 자산 설정은 별도 모듈에 모은다. 이 모듈은 공개 자산 경로, 반복 배율, 색 공간, 필터,
품질별 활성 맵을 정의한다. 자원 생성기는 텍스처를 주입받아 벽, 바닥, 천장, 형광등 형상과
재질을 만들고 반복 호출되는 정리에서도 각 GPU 자원을 한 번만 해제한다.

셀의 중심 간 거리는 계속 1이고 서버 이동 명령도 그대로다. 벽 면은 기존 논리 경계에 두되
높이와 카메라 비율을 조정해 복도를 좁게 느끼게 한다. 출구, 감지기, 덫은 기존 벽 좌표를
사용하므로 판정과 표시 위치가 어긋나지 않는다.

## 경기 오버레이

경기 화면에는 다음 계층만 항상 노출한다.

1. 전체 화면 3D 캔버스
2. 네 모서리 촬영 프레임과 좌상단 `REC`, 녹화 경과 시간
3. 중앙 십자선
4. 중앙 하단 5칸 핫바
5. 우측 하단 미니맵
6. 필요할 때만 여는 상호작용 서랍

기존 상단 경기 상태 막대와 왼쪽 하단 이벤트 로그는 화면에서 제거한다. 게임 상태 문구는
스크린 리더가 읽을 수 있는 숨김 영역으로 남기고, 실제 상호작용 UI는 기존 서랍에서 계속
사용한다. 녹화 시간은 경기 화면이 마운트된 뒤의 경과 시간이며 권위적인 경기 제한 시간과
혼용하지 않는다.

핫바 모델은 역할에 따라 기존 두 개의 실제 행동 슬롯을 유지하고 나머지 세 칸을 잠긴 빈
슬롯으로 채워 항상 다섯 칸을 반환한다. 도망자의 미확정 아이템은 구현하지 않는다. 슬롯은
픽셀 테두리 대신 반투명 검정, 얇은 금속 테두리, 부드러운 선택광을 사용한다.

## 반응형과 성능

- 중간 품질은 장치 DPR 상한 1.5, 저품질은 DPR 1을 유지한다.
- 저품질에서는 normal/roughness 맵과 장식용 벽 몰딩을 생략한다.
- 형광등은 모든 셀마다 실제 광원을 만들지 않고 발광 메시와 제한된 기존 조명만 사용한다.
- 700px 이하에서는 핫바 슬롯을 정사각형에 가깝게 축소하고 보조 문구를 숨긴다.
- 400px 폭에서도 핫바와 미니맵이 화면 밖으로 나가지 않으며 가로 스크롤을 만들지 않는다.
- 텍스처 로딩 실패 시 재질의 기본 노란색으로 렌더링해 게임 진행을 막지 않는다.

## 자산과 권리 기록

네 PNG는 사용자가 프로젝트 적용을 위해 제공한 자산으로 `apps/web/public/textures/backrooms/`
아래에 소문자 파일명으로 저장한다. 크기, 바이트 수, SHA256, 제공 경로와 사용 목적을
`docs/third-party-assets.md`에 기록한다. 원본 파일명과 저장소 파일명 대응도 함께 남긴다.

## 검증

- 테마 기본값, 품질별 텍스처 선택, 반복·색 공간 설정을 단위 테스트로 고정한다.
- 자원 생성과 중복 해제를 기존 렌더링 테스트로 검증한다.
- 핫바가 역할과 관계없이 정확히 다섯 칸이고 미확정 기능을 활성화하지 않는지 검사한다.
- 캠코더 시간 포맷과 접근성 문구를 컴포넌트 테스트로 검사한다.
- Playwright에서 데스크톱과 400px 화면의 오버레이 위치, 화면 내 배치, 가로 스크롤 부재를
  검사한다.
- `/preview`에서 데스크톱과 모바일 스크린샷을 남겨 벽지, 좁은 복도, 촬영 프레임, 핫바,
  미니맵을 육안 검토한다.
- 관련 테스트와 웹 타입 검사만 로컬에서 실행하고 전체 검증은 MR 파이프라인 결과로 확인한다.

## Git과 전달

현재 `feat/S15P21C204-279-backrooms-ui-redesign` 브랜치에서 설계, 재질, HUD, 문서·검증 단위로
커밋한다. 각 커밋 마지막 문단에는 `S15P21C204-279`를 단독 줄로 둔다. 전체 UI 변경을 마친 뒤
한 번만 push하고, 사용자가 요청하면 기존 템플릿과 유사한 제목 및 다섯 개 필수 항목으로 MR을
작성한다.
