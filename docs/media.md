# 미디어

2026-09-15 기준. 얼굴·음성은 LiveKit Cloud로 전달하고 권한은 게임 서버가 정한다. 제품 규칙(누구의 얼굴·음성이 언제 들리는가)은 [기획서 11장](spec/current.md#11-얼굴음성효과음)이 기준이며, 이 문서는 구현 구조와 수명·권한 경계를 설명한다.

## 1. 구성과 소유

| 영역        | 위치                                                                                      | 책임                                                                    |
| ----------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 원본 장치   | `apps/web/src/features/devices`                                                           | 카메라·마이크 취득과 종료                                               |
| 가공·게시   | `apps/web/src/features/media` (`face-compositor`, `track-publisher`, `media-session`)     | 160×160 흑백 마스크 얼굴, 선택 마이크 게시, 원격 트랙 부착, 음향 그래프 |
| 세대·발급   | `server/src/media` (`MediaCoordinator`, `MediaGenerationRegistry`, `GrantIssuer`)         | 미디어 세대, Identity·토큰 발급, 사용량 예약                            |
| 권한·바인딩 | `server/src/media` (`AudibilityPolicy`, `MediaPolicyBindings`, `TrackRegistry`)           | 서버 프레임 기준 가청 판정, 확인된 트랙 SID만 바인딩                    |
| 회수·복구   | `server/src/operations` (`OperationJournal`, `UsageBudget`, `RecoveryCleanupBindings` 등) | 원격 회수 확인, 저널·사용량 내구 기록, 재시작 복구                      |
| 준비 상태   | `server/src/health` (`Readiness`, `ReservationReadiness`)                                 | capability·예산·저널·예약을 대조해 발급 허용 여부 결정                  |

웹은 서버가 준 grant와 바인딩만 사용한다. metadata·닉네임으로 트랙 소유자를 추측하지 않는다.

## 2. 세대와 수명

게임 참가와 미디어 연결 세대는 수명이 다르다.

- **세대 교체**(`retireMediaGeneration`): 이전 세대의 게시 트랙·수신 트랙·음성 그래프·SDK 연결·텍스처를 정리한다. playerId·경기 참가·게임 Room 연결은 유지한다. 이전 Identity의 원격 회수가 확인되기 전에는 새 Identity·토큰을 발급하지 않고, 폐기한 Identity를 재사용하지 않는다.
- **참가 종료**(`endParticipation`): 개인 종료·퇴장·경기 종료. 개인 결과와 재경기에 필요한 Room 연결은 남길 수 있다. 실제 퇴장·게임 연결 상실에서는 장치·Worker·타이머까지 정리한다.
- **장치 장애**: 카메라·추론 장애만으로 참가를 끝내지 않는다. 키보드 입력과 기본 얼굴로 전환한다. 마이크 장애는 음성 송출만 정리한다.
- **단계 전환**: 팀 연습(팀별 인스턴스 2개) → 경기(1개)로 넘어갈 때 연습 세대를 회수한 뒤 경기 세대를 발급한다. 회수가 확인되지 않으면 MAP_FINALIZING에서 기한 후 ABORTED로 끝내고 미확인 기록과 발급 차단은 유지한다.
- **로컬 정리와 원격 회수는 다르다.** SDK disconnect 성공이 서버의 원격 회수 확인을 대신하지 않는다.

## 3. 권한 방식 — `publisher-permissions`

현재 운영 방식이다(2026-09-11 내부 시험 승인, D-2026-09-15-01로 최대 10방까지 확대).

1. 서버가 권위 프레임과 확인된 바인딩으로 송신자별 수신 허용 대상과 트랙 SID를 계산한다.
2. 송신 앱이 LiveKit `setTrackSubscriptionPermissions(false, permissions)`로 적용한다. 수신 토큰은 `canSubscribe=true`지만 허용 목록 밖 수신자의 직접 구독은 SFU가 막는다.
3. 게시 전 기본 차단. 세대 종료·재연결·정책 갱신이 1.5초 이상 멈추면 허용을 철회한다.
4. 토큰 회수·잔존 정리·사용량·API 예산·SSO·초대 검증은 이 방식과 무관하게 유지한다.

**수용한 위험.** 변조한 송신 앱은 자기 허용 목록을 넓혀 금지 수신자에게 트랙을 보낼 수 있다(2026-09-13 실제 Cloud 진단에서 재현). 친구 초대방 범위에서 이 위험을 수용하고 공개 안내로 보완한다. 서버 단독 통제로 보고하지 않는다.

**보이지 않는 얼굴도 도착할 수 있다.** 경기에서는 다른 참가자 최대 5명의 얼굴 트랙을 미리 수신하고 시야에 들어온 캐릭터에만 표시한다. 화면 가시성은 bytes 수신 차단이 아니다.

`publish` 루프는 방 범위(matchId·mediaInstanceId)를 먼저 확인한 뒤 권한을 평가하고, 트랙 권한 검사는 해당 트랙을 가진 바인딩만 조회한다(`TrackRegistry.bindingsForTrack`). 이 순서가 바뀌면 방 수에 제곱으로 비용이 늘어 여러 방 동시 발급에서 tick 과부하가 난다(S15P21C204-251).

## 4. 음성·효과음과 사용자 제어

- 가청: 통로 최단 셀 거리 5 이하에서 새로 허용, 6까지 유지, 6 초과 해제. 거리·코너 수로 볼륨과 저역 필터, 좌우는 StereoPanner. 로딩·카운트다운·개인 종료·탭 숨김·권위 상실 때 출력을 잠근다.
- 확인음(660Hz·350ms)은 장치 점검·팀 연습·개인 체험에서만 재생하며 카메라·마이크를 취득하지 않는다.
- 마이크 입력 막대는 입력 존재 확인용이다. 녹음·저장·업로드하지 않는다.
- 듣는 음량(기본 70%), 전체 소리 끄기, 친구별 목소리 끄기는 서버가 허용한 소리에만 적용한다. 서버의 금지·출력 잠금을 열지 않는다. 같은 방 재경기에서는 유지하고 퇴장·연결 상실·개인 체험 재시작에서 초기화한다. 브라우저 저장소에 남기지 않는다.
- 효과음(발소리 4셀, 감지기·덫 6셀)은 코드 생성 PCM이며 같은 서버 사건을 한 번만 재생한다.

## 5. 증거 수집(시험용)

- `media-evidence.ts`(S15P21C204-246): 게시·수신 트랙, 음성, 구독 무결성을 모은다. `forbiddenButSubscribed`는 위반, `mutedButSubscribed`는 위반 아님, `authorizedButUnsubscribed`는 수신 실패 단서다. 구독 상태는 SDK가 보고한 값을 싣는다.
- 제품 앱 측정(S15P21C204-221): `?metrics=1`일 때만 렌더 fps·긴 프레임·모델별 추론 지연·미디어 상태 전이를 경기 단위로 모아 `window.__kkakkungMetrics.read()`로 노출한다. 참가자 id·원본 얼굴·음성은 넣지 않는다.

## 6. 보류된 split 서버 전달 (`server-forwarding`)

S15P21C204-215에서 만든 “서버 단독 통제” 후보다. D-2026-09-15-01로 보류했고 영구 폐기는 아니다. 코드는 명시적인 `server-forwarding` 조립에서만 동작하며, 운영 환경 설정(`MEDIA_SUBSCRIPTION_MODE`)은 이 값을 받지 않는다.

**구조.** 참가자마다 CAMERA 전용 얼굴 게시 연결(수신 불가 토큰)과 개인 MIC 게시·수신 방을 둔다. 서버가 `forwardParticipant`로 필요한 상대의 얼굴과 허용된 음성만 개인 방에 전달하고, 거리 밖 음성은 remove ACK와 실제 부재로 차단한다. 송신 앱의 허용 목록을 권한 근거로 쓰지 않는다.

**구현·병합된 것.** 웹 두 연결 수명·게시·바인딩(!139), 소유 기록과 묶음 회수(!140), 발급·사용량 예약(!141), 서버 가청 제어·SID 대조·늦은 전달 봉쇄(!142), 전달 intent·발급 전 예약의 내구 기록(!146).

**실제 Cloud로 확인한 것**(모두 합성 미디어, 운영 자원 미사용).

| 사례         | 결과                                                                                                        |
| ------------ | ----------------------------------------------------------------------------------------------------------- |
| MC-PUBLIC-01 | publisher 목록 변조로 금지 수신 우회 재현. 격리 방 전달의 허용·직접 차단·제거 후 차단·재허용 확인           |
| MC-PUBLIC-02 | 제품 웹 어댑터 두 페이지·네 연결로 얼굴 유지·음성 차단·재허용. 허용 약 265ms, 원본과 전달본 SID가 같게 관측 |
| MC-PUBLIC-03 | 방 생성 전·생성 후·삭제 뒤 120초 안정화 후 재생성에서 미입장 토큰 거절과 새 SID 확인                        |

**재개하려면 남은 것.**

- 미확인 forward의 해소 근거: TTL 만료·방 삭제·한 번의 부재 조회만으로 늦은 효과가 없다고 판단하지 않는다. 공급자 최종성 근거가 필요하다.
- 실제 지연·프로세스 종료를 포함한 구성요소 Cloud 시험(MC-PUBLIC-04, 미작성), 9개 분리 capability를 실제 근거로 생성해 제품 HTTP·Room·웹을 연결한 인수.
- 용량: 6인 한 경기가 SDK 연결 12개, 보수 예약 72자원이다. 10경기면 원본 연결만 120개로 Build 플랜 동시 참가자 100을 넘는다. 복제 참가자의 quota·과금 반영을 먼저 확인해야 한다.
- 새 저널 필드(`splitOwnership`, `forwardIntents`, `reservationIntent`)를 쓴 저장소는 구 reader로 롤백할 수 없다. reader 배포 → 인수 → writer 활성화 순서를 지킨다.
