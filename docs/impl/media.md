# 미디어 구현 명세

## 1. 역할과 경계

미디어 파트는 두 쪽으로 나뉜다. 서버 `server/src/media`는 LiveKit 연결 권한(grant)의 발급·교체·회수, 발행 트랙 검증, 수신자별 바인딩과 음성 정책 계산, LiveKit 서버 API 호출 예산, 월 사용량 가드를 소유한다. 웹 `apps/web/src/features/media`는 가공 얼굴 합성, 게시, 검증된 원격 트랙만 붙이는 수신, WebAudio 음성·효과음 그래프를 소유하고, `devices`·`vision`은 원본 카메라·마이크와 얼굴 랜드마크를 공급한다. 방 단계·명령·좌석은 [server.md](server.md), 화면 표시는 [web.md](web.md), 메시지 형상은 [protocol.md](protocol.md)가 소유한다. 이 문서는 Room이 미디어를 부르는 지점까지 포함한다.

서버 미디어 모듈은 `livekit-server-sdk`, Node 내장 모듈(`node:crypto`·`node:fs`·`node:fs/promises`·`node:path`), `operations/`·`health/`·`observability/`의 내부 모듈만 import한다. 웹 미디어 모듈은 SDK를 정적으로 import하지 않고 `loadLiveKit()`의 동적 `import('livekit-client')` 결과를 주입받으며, 디렉터리 밖으로는 `../vision/face-sensor`·`../vision/sensor-types`만 import한다. 웹 쪽 조립점은 `features/input/InteractionRuntime.ts`, HTTP·Room 메시지 송수신은 `app/product-runtime.ts`다.

ESLint는 `apps/web/**/*.{ts,tsx}` 전체에 `no-restricted-imports`로 `@kkakkung/game-core`, `@kkakkung/game-core/*`, `**/game-server/**`, `**/server/**`, `**/packages/game-core/**`를 금지한다. 따라서 웹 미디어는 서버 미디어 코드를 가져다 쓰지 못하고, 둘 사이의 형상은 `@kkakkung/protocol`과 웹 쪽 소비자 사본(`media-types.ts`)으로만 맞춘다. 서버 미디어 쪽에는 별도 import 제한 규칙이 없다.

## 2. 발급 조건

### 2.1 방 단계별 발급과 연결

미디어는 연습(`TEAM_PRACTICE`)부터 경기(`PLAYING`)까지의 인스턴스에서만 존재한다. **대기실(`LOBBY`)과 장치 점검(`DEVICE_CHECK`)에서는 어떤 grant도 발급되지 않는다.** 두 단계에는 연습·경기 인스턴스가 없어 `mediaScopeFor`가 `null`을 돌려주고, 웹도 이 단계에서 grant를 요청하거나 SDK Room에 연결하지 않는다.

서버 판정은 두 겹이다. Room의 `mediaScopeFor`는 단계가 `RESULT`·`ABORTED`가 아니고, 플레이어의 Colyseus 연결이 살아 있고, 요청 `purpose`와 같은 종류(`practice`/`game`) 인스턴스에 속하고, 코어 기준 개인 상태가 `ACTIVE`이고, 그 인스턴스에 `mediaInstanceId`가 있을 때만 범위를 준다. 이어 `MediaGenerationRegistry.eligible`이 마지막 권위 프레임을 보고 `practice`는 프레임 단계 `TEAM_PRACTICE`, `game`은 `GAME_LOADING`·`COUNTDOWN`·`PLAYING`일 때만 허용한다. 연습 인스턴스의 `mediaInstanceId`는 미디어가 켜져 있을 때만 만들고, 경기 인스턴스는 항상 만들되 미디어가 없으면 드라이버에 `null`로 붙인다.

| 방 단계          | 서버 발급 적격                                    | 웹 첫 grant 요청 | 웹 교체(복구) grant | 웹 SDK 연결 허용(`MEDIA_CONNECT_PHASES`) | 웹 오디오 출력                        |
| ---------------- | ------------------------------------------------- | ---------------- | ------------------- | ---------------------------------------- | ------------------------------------- |
| `LOBBY`          | 불가: 인스턴스 없음 → 409 `NOT_READY`             | 안 함            | 안 함               | 거부 `PHASE_NOT_ALLOWED`                 | 잠금                                  |
| `DEVICE_CHECK`   | 불가: 인스턴스 없음 → 409 `NOT_READY`             | 안 함            | 안 함               | 거부 `PHASE_NOT_ALLOWED`                 | 잠금                                  |
| `TEAM_PRACTICE`  | `purpose=practice`, `ACTIVE`, 미디어 켜짐         | 함               | 함                  | 허용                                     | 열림(본인 `ACTIVE`·탭 활성)           |
| `MAP_FINALIZING` | 불가: 연습 인스턴스는 이미 분리, 경기 인스턴스 전 | 안 함            | 안 함               | 허용                                     | 잠금                                  |
| `GAME_LOADING`   | `purpose=game`, `ACTIVE`                          | 함               | 함                  | 허용                                     | 잠금                                  |
| `COUNTDOWN`      | `purpose=game`, `ACTIVE`(첫 발급도 가능)          | 안 함            | 함                  | 허용                                     | 잠금                                  |
| `PLAYING`        | `purpose=game`, `ACTIVE`(첫 발급도 가능)          | 안 함            | 함                  | 허용                                     | 열림(본인 `ACTIVE` 또는 관전·탭 활성) |
| `RESULT`         | 불가: `mediaScopeFor`가 명시적으로 거절           | 안 함            | 안 함               | 거부                                     | 잠금, 참가 종료로 세대 회수           |
| `ABORTED`        | 불가: `mediaScopeFor`가 명시적으로 거절           | 안 함            | 안 함               | 거부                                     | 잠금, 참가 종료로 세대 회수           |

### 2.2 참가자 조건

단계 외에 서버가 보는 참가자 조건은 아래가 모두 참이어야 한다.

| 조건                                                                 | 판정 위치                                 |
| -------------------------------------------------------------------- | ----------------------------------------- |
| 제품 세션 Bearer가 유효하고 요청 `matchId`가 그 방의 현재 경기       | 라우트                                    |
| Colyseus 연결이 살아 있고 코어 개인 상태가 `ACTIVE`                  | `mediaScopeFor`                           |
| 운영 준비(READY)·입장 `OPEN`·엄격 제품에서 `media.canIssue()`        | 라우트 `operationsReady`, Room `canStart` |

| 게임 연결이 미디어 수명기에 `connected`로 등록됨                     | `MediaLifecycle.isGameConnected`          |
| 이 경기에서 그 플레이어가 종료 래치(`ended`)에 걸리지 않음           | `GenerationTransition.isAllowed`          |
| 프레임 명단에 `ACTIVE`로 있거나 관전 링크로 있음                     | `registry.eligible`                       |

| 발급된 비폐기 세대의 대상 수 합계가 `maxConcurrentParticipants` 이하 | `canIssue`                                |

## 5. 발급 거절과 세대 전이

### 5.1 발급 경로

`prepareGeneration` → `GenerationTransition.replace`(플레이어별 직렬화) → 이전 세대가 있으면 원격 회수 확인과 웹 로컬 `closed` 보고를 모두 기다림 → `GrantIssuer.prepare`(같은 `(matchId, playerId)`는 다시 직렬화) → 사용량 예약 → 내구 기록(PREPARED) → 재검사 → JWT 서명 → 재검사 → `ready`. 서명 전에 예약·기록이 끝나야 하며, 서명 도중 창이 닫히거나 만료 초에 닿으면 그 세대를 회수하고 거절한다.

사용량 예약은 미디어 방마다 임대(lease) 하나를 공유한다. 예약 결과는 네 가지다.

| 예약 결과                                                       | 임대 상태                                          | 발급기 결과                          |
| --------------------------------------------------------------- | -------------------------------------------------- | ------------------------------------ |
| 거절이고 그 예약이 디스크에 남지 않았으며 앞선 조각 예약도 없음 | 그대로                                             | `false` → `BUDGET_EXHAUSTED`(미발급) |
| 거절이지만 그 예약 id가 이미 디스크에 있거나 `STORAGE_FAILURE`  | `retiring`, 예외 `RESERVATION_UNCONFIRMED`         | 예외 → `REMOTE_UNAVAILABLE`          |
| 분리 모드 2단위 중 일부만 예약됨                                | `retiring`, 예외 `PARTIAL_RESERVATION_UNCONFIRMED` | 예외 → `REMOTE_UNAVAILABLE`          |
| 임대가 이미 `retiring`                                          | —                                                  | `false` → `BUDGET_EXHAUSTED`         |

단위 수는 단일 모드 1, 분리 모드는 대상 수 ÷ 6 올림(1 또는 2, 그 밖이면 `INVALID_LEASE_CAPACITY`)이다. 첫 조각은 5분, 이후 1분이고, 성공하면 임대 끝 시각을 max(지금, 기존 끝) + 조각 길이로 늘린다. 남은 시간이 60,000ms보다 크면 예약을 새로 하지 않고 `true`를 돌려준다.

### 6.4 Room 쪽 미해결 미디어와 `RETIRING` 좌석

### 8.2 월 사용량 가드(서버)

`MonthlyUsageMeter`는 유지보수 루프마다 "LiveKit에 연결이 확인되고 끝나지 않은 참가자 수 × 경과 시간"을 더한다. 사용 분 = (기준 시각이 이번 주기 안이면 기준 분, 아니면 0) + ceil(누적 ms / 60,000). 남은 분 = max(0, 한도 − 사용 분). 남은 분 ≤ 예비 분이면 `blocked`. 기준 시각 이전 시간과 뒤로 간 시계는 세지 않는다. 기준 값이 바뀌거나 주기가 바뀌면 0부터 다시 센다. 30,000ms마다(종료 때는 즉시) 파일에 쓰며, 쓰기 실패는 다음 관찰에서 다시 시도한다.

가드는 연습 시작 때만 본다. 차단이면 장치 점검에 머물고 사유 `MEDIA_MONTHLY_LIMIT`(공개 준비 문제 `MEDIA_BUDGET_EXHAUSTED`)를 보인다. 진행 중인 경기는 멈추지 않는다. 가드가 응답하지 못하면(예외) 새 경기를 막는다. 차단 상태가 바뀔 때만 `media.budget.near_limit` 이벤트를 남긴다.

### 10.2 얼굴 조건 안내

휘도 표본은 500ms마다 원본을 32×32(주변)·64×64(얼굴) 스크래치 Canvas에 줄여 통계만 뽑는다. 판정 우선순위는 큰 회전 → 안경 반사 → 역광 → 가림 → 얼굴 없음이다.

| `turned-away`  | \|yaw\| > 60°                                               | 고개를 화면 쪽으로 돌려 주세요.                                      |
| `glare`        | 눈 영역(표본 크기 × 0.16 상자) 포화(휘도 ≥ 245) 비율 ≥ 0.08 | 안경에 조명이 반사되고 있어요. 고개나 조명 각도를 조금 바꿔 주세요.  |

## 13. 주요 흐름

1. 방장이 `ROOM_START`를 보내면 Room은 미해결 미디어·월 사용량 가드·경기 좌석을 확인하고 역할 팀마다 연습 인스턴스와 `mediaInstanceId`를 만든다. 드라이버가 매 틱 권위 프레임을 코디네이터에 넘긴다.
2. 웹은 개인 뷰의 `gameScope.kind='practice'`를 보고 POST `/api/media/grants {matchId, purpose:'practice'}`를 보낸다. Room은 첫 프레임을 기다린 뒤 `prepareGeneration`을 부르고, 발급기가 예약 → 기록 → 서명을 거쳐 grant를 돌려준다. Room은 `MEDIA_PREPARED`를 다음 틱에 적용해 플레이어의 현재 세대를 기록한다.
3. 웹은 SDK Room에 `autoSubscribe=false`로 연결하고 가공 얼굴과 마이크를 게시한 뒤 `media-bindings-refresh`를 보낸다. LiveKit 웹훅이나 5초 재조회가 트랙을 검증하면 서버는 수신자마다 바인딩을 만들고 구독을 연다. 매 프레임 `audio-policy`가 거리별 음성을 조정한다.
4. 전원 연습 준비가 끝나면 Room은 연습 인스턴스를 `phase-change`로 회수하고 `MAP_FINALIZING`에서 회수 확인을 기다린다. 경기 인스턴스를 연 뒤 웹은 이전 세대를 로컬 회수하고 `closed`를 보고한 다음, `previousReceiverGeneration`을 담아 `purpose:'game'` grant를 요청한다.
5. `GAME_LOADING`에서 서버 바인딩의 자기 항목이 얼굴 SID를 확인해야 Room의 로딩 장벽이 풀리고, 웹도 연결 상태 `connected`와 자기 얼굴 바인딩이 있어야 `LOAD_READY`를 보낸다. 이어 `COUNTDOWN`·`PLAYING`으로 간다.
6. 경기 중 포획·탈출이면 코어가 `RETIRE_PLAYER personal-ended`를 내고, 결과가 정해지면 `RETIRE_INSTANCE round-ended`와 `RESULT` 프레임이 남은 세대를 회수한다. 웹은 결과 단계에서 참가를 끝내며 장치를 닫는다.
7. SDK가 순간 끊기면 웹은 `recovering`을 보고하고, 실패하면 `failed` 보고 후 같은 인스턴스의 교체 grant를 한 번 요청한다. 서버는 `reconnect`로 이전 세대를 회수하고 원래 10초 창 안에서만 새 세대를 준다.
8. 게임 연결이 끊기면 Room은 `connection-lost` 회수를 걸고 좌석을 `RETIRING`으로 둔다. 회수가 `unknown`이면 재시도 엔진이 1초·2초·4초 간격으로 최대 3회 다시 시도하고, 확인되면 `MEDIA_RETIRED confirmed`가 Room에 와 좌석이 풀린다. 10초 안에 확인되지 않으면 `UNRESOLVED`가 되어 발급이 잠기고, 운영자가 `retry-retirement`로 한 번 더 시도할 수 있다.

## 16. 확인된 한계

- **분리 모드 미연결.** `server-forwarding` 경로(서버 분리 정책 층·전달 edge·웹 두-Room 연결)는 코드와 Cloud 시험에 있으나 `MEDIA_SUBSCRIPTION_MODE` enum에 없어 제품 설정으로 켤 수 없다. 구현으로 세지 않는다.
- **거절 하나가 라운드를 끝냄.** Room은 현재 요청의 `MEDIA_PREPARED`가 `ready`가 아니면 거절 코드(5.2절 표의 8개 전부)와 무관하게 `ABORTED MEDIA_UNAVAILABLE`로 끝낸다. 한 명의 교체 실패도 6명 라운드를 무효로 만든다. 관전 중인 종료 도망자의 실패만 예외로, 그 사람의 수신만 멈춘다(S15P21C204-380). 사용자 결정으로 의도된 동작이다([결정 정정표](../spec/decisions.md), 2026-09-24).
- **웹·서버 단계 불일치.** 웹 `MEDIA_CONNECT_PHASES`는 `MAP_FINALIZING`을 허용하지만 서버는 그 단계에 발급하지 않는다(제품 런타임은 그 단계에 요청하지 않아 실해는 없음). 서버는 `COUNTDOWN`·`PLAYING`에서도 첫 발급을 허용하지만 웹은 이 두 단계에서 교체만 요청한다.
- **음성 계산과 출력 잠금 불일치.** 서버는 `GAME_LOADING`·`COUNTDOWN`에서도 음성·효과음 정책을 계산해 보내지만 웹은 이 단계에서 출력을 잠근다. 잠금 중 효과음은 버려지고 다시 재생되지 않는다.
- **미디어 없는 서버와 웹 로딩.** 웹은 `/api/config`의 `mediaEnabled`를 읽지 않는다. 엄격 제품 프로필에서는 미디어가 없으면 `operationsReady`가 `media.canIssue`를 요구해 연습 자체가 시작되지 않으므로 이 차이가 드러나지 않는다. 비엄격(개발·시험) 조립에서 미디어 없이 일반 방을 돌리면 웹이 연결·얼굴 바인딩을 기다려 `LOAD_READY`를 보내지 않는다(데모 방만 예외).
- **refresh payload.** 웹은 `media-bindings-refresh`에 미디어 범위와 `lastBindingRevision: 0`을 담아 보내지만, 서버는 payload를 읽지 않고 저장된 마지막 바인딩을 다시 보낸다. 쓰이지 않던 `mediaRefreshRequestSchema`는 지웠다(S15P21C204-381).
- **웹 포트 미사용.** `InteractionDeps.requestMediaGrant`·`reportMediaStatus`는 런타임 안에서 호출되지 않는다. 제품 경로는 `product-runtime.ts`의 `post`로 직접 요청한다.
- **정책 배열 상한 없음.** `audioPolicySchema`의 `voices`·`effects`에는 개수 상한이 없다(`publisherPermissions`만 5).
- **네임스페이스 규칙 차이.** 설정은 `SERVICE_NAMESPACE`에 `--`를 허용하지만 registry는 `--`가 있으면 생성 단계에서 예외를 던진다.
- **두 사용량 계량기(바꾸지 않기로 결정, [결정 정정표](../spec/decisions.md) 2026-09-24).** 서버 가드(참가자 수×시간 자체 집계, `LIVEKIT_BILLING_CYCLE_DAY` 주기, 기본 예비 300분, 새 경기 차단)와 호스트 감시 잡(Analytics API, UTC 달력 월, 잡에 고정된 5000/4000/4500분, 알림만)은 서로 값을 나누지 않는다. 주기 경계와 임계가 다르다.
- **사용량 스크립트.** 종료 코드 3은 `ANALYTICS_UNAUTHORIZED`일 때만이고 연결 불가·HTTP 오류는 1이다(머리 주석을 맞췄다, S15P21C204-381). `USAGE_POLICY.maxCoverageGapMs`는 정의만 있고 쓰이지 않는다.
- **운영 재시도 식별자.** 운영 상태 응답의 `unresolvedRetirementIds`와 미해결 이벤트 `media.retirement.unresolved`의 `retirementId`로 재시도할 회수를 알 수 있다(S15P21C204-402). 아직 재시도 기록이 만들어지지 않은 미해결은 이벤트에 식별자가 없다.
