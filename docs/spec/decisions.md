## 연결 계약 보완

[EXEC-CONTRACT-3 공통 원본](../execution/common.md)과 [검사 가능한 타입](../execution/contracts/types.ts)을 적용한다. 기존 명령의 접수/종결, 수신자·송신자 세대, 센서별 관측 시각 등의 계약을 유지하고 맵 영역·fallback 출처, 연습/본경기 논리 인스턴스, 미디어 초기화와 준비·입장 상태의 구분을 보완했다. HTTP 매칭 처리 전 Origin 검사와 외부 접근을 격리한 배포 시험 순서도 담당 계획에 반영했다.

이 계약·fixture의 검사 통과는 계획 정합성 증거다. 실제 제품 구현, Cloud 권한, 6대 완주, 10방 성능의 통과를 뜻하지 않는다.

## 내부 6인 시험의 미디어 권한 방식 (2026-09-11)

사용자 승인: **“내부 테스트 우선 — 송신 허용 목록 방식 적용”**.

`MEDIA_SUBSCRIPTION_MODE=publisher-permissions`는 정상 팀 클라이언트 6명·1방에 한해 선택한다. 서버가 권위 프레임과 확인된 미디어 바인딩으로 송신자의 수신 대상·트랙 SID를 정하고, 송신 앱이 LiveKit의 `setTrackSubscriptionPermissions(false, permissions)`에 적용한다. 수신 토큰에는 `canSubscribe=true`가 필요하지만 임의 수신자의 직접 구독은 송신 허용 목록으로 SFU에서 차단한다. 게시 전 기본 차단, 세대 종료·재연결·정책 갱신 1.5초 중단 시 허용 철회를 적용한다.

이 승인은 변조된 송신 앱까지 서버 단독으로 통제한다는 기존 조건의 내부 시험 예외다. 공개 운영의 서버 단독 통제 통과로 보고하지 않는다. 기본값 `server-controlled`는 유지하며 두 모드의 실제 Cloud capability 보고서는 혼용하지 않는다. 토큰 회수·잔존 정리·사용량·API 예산·SSO·초대 검증은 유지한다. 합성 Cloud 시험과 실제 6대 게임 완주는 별도 결과다.
