## 공부한 것

### 1. 핀홀 카메라 모델

```
x = K [R | t] X
```

- `X` : 월드 3D 좌표 (동차좌표)
- `[R|t]` : 외부 파라미터 (카메라의 위치와 방향)
- `K` : 내부 파라미터 (초점거리 f, 주점 cx/cy)
- `x` : 이미지 픽셀 좌표

핵심 직관: **거리 d에 있는 높이 h인 물체는 화면에서 `f·h/d` 픽셀이 된다.**
멀수록 작아지고, 줌인(f 증가)하면 커진다. 당연한 얘기지만 이게 계산의 전부다.

### 2. 호모그래피 — 평면에만 쓰는 특수한 변환

월드 점이 **한 평면 위에 있으면** Z=0으로 두고 3열을 지울 수 있다.

```
x = K [r1 r2 r3 t] (X, Y, 0, 1)ᵀ = K [r1 r2 t] (X, Y, 1)ᵀ = H (X, Y, 1)ᵀ
```

즉 **평면 ↔ 이미지는 3×3 행렬 하나로 완전히 표현된다.**

| 항목 | 값 |
|---|---|
| 자유도 | 8 (9개 원소 - 스케일 1) |
| 최소 대응점 | 4개 |
| 추정 방법 | DLT (Direct Linear Transform) + SVD |

**이 프로젝트에 왜 중요한가**: 광고판은 **평면이고 움직이지 않는다.**
움직이는 건 카메라뿐이다. 그러면 연속 두 프레임의 관계는 호모그래피 하나로
완전히 기술된다. → 어제 의문 3번(객체 추적기가 맞나?)의 답이 나왔다.
**사람 추적용 트래커는 필요 없다. 호모그래피면 충분하고 더 정확하다.**

### 3. RANSAC — 이상치가 섞여도 버티기

대응점 중에는 틀린 게 섞인다(선수가 움직여서 생긴 매칭 등).
최소제곱을 그냥 돌리면 이상치 하나가 전체를 망친다.

```
반복:
  1. 최소 개수(4점)를 무작위로 뽑아 모델 추정
  2. 나머지 점 중 이 모델에 맞는 개수(inlier) 센다
  3. inlier가 가장 많은 모델 채택
```

**inlier 비율이 곧 신뢰도**가 된다. 이 값이 낮으면 "선수 같은 동적 물체가
추정을 오염시켰다"는 신호로 쓸 수 있다.

### 4. 지면 호모그래피의 한계 — 이걸 놓칠 뻔했다

축구장 캘리브레이션은 **지면 평면** 기준이다. 그런데 광고판은 **수직으로 서 있다.**

```
H = λK[r1 r2 t]   ← r3 (깊이 방향 회전축) 이 없다!
```

지면 위 점 (X, Y, 0)은 투영할 수 있지만, 광고판 윗변 (X, Y, 0.9)는 **투영할 수 없다.**
`K·r3` 항이 H에 들어있지 않기 때문이다.

**해결**: K를 복원하면 r1, r2를 정규화해서 얻을 수 있고, `r3 = r1 × r2`로 만들 수 있다.
그러면 전체 투영행렬 `P = K[r1 r2 r3 t]`가 완성되어 수직 물체도 투영된다.

K 복원은 회전행렬의 성질에서 나온다 (r1 ⊥ r2, |r1| = |r2|):

```
h1ᵀ ω h2 = 0
h1ᵀ ω h1 = h2ᵀ ω h2       (ω = K⁻ᵀK⁻¹, 절대원뿔의 상)
```

주점을 이미지 중심에 두고 `K = diag(f, f, 1)`로 가정하면 미지수가 f 하나뿐이라
식 하나로 풀린다. 주점을 원점으로 옮긴 좌표에서:

```
f² = -(a1·a2 + b1·b2) / (c1·c2)      h1=(a1,b1,c1), h2=(a2,b2,c2)
```

### 5. OCR은 어떻게 동작하는가 — 2단계 구조

| 단계 | 하는 일 | 대표 모델 |
|---|---|---|
| Detection | 이미지에서 텍스트 영역 찾기 | CRAFT, DBNet |
| Recognition | 잘라낸 조각을 문자열로 | CRNN, SVTR |

**Recognition 단계가 핵심이다.** 이 모델들은 입력을 **고정 높이(보통 32px 또는 48px)로
리사이즈**한 뒤 가로 방향 시퀀스로 읽는다.

여기서 결정적인 사실이 나온다:

> **원본 텍스트 높이가 32px보다 작으면 업샘플링해서 넣는 것이고,
> 없는 정보는 만들어지지 않는다.**

그래서 **텍스트 높이(정확히는 대문자 높이 = cap height)에 물리적 임계가 존재한다.**
이게 어제 의문 1번의 이론적 배경이다. 로고 가로폭이 아니라 **글자 높이**가
인과 변수라는 것도 여기서 나온다.

### 6. CTC Loss — 정렬 없이 시퀀스 학습

Recognition은 "이미지 프레임 시퀀스 → 문자 시퀀스"인데 둘의 길이가 다르고
어느 프레임이 어느 글자인지 정답이 없다.

CTC는 **blank 토큰**을 넣고 가능한 모든 정렬을 marginalize해서 이 문제를 푼다.
`--HH-EE-LL-LLO-` → 중복 제거 + blank 제거 → `HELLO`

부작용: 같은 글자가 연속될 때(`LL`) blank가 없으면 하나로 합쳐진다.
작은 글자에서 오인식이 잘 나는 이유 중 하나.
