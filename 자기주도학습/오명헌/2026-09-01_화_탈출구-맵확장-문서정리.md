# 학습 일지 — 2026-09-01 (화)

> **까꿍(KKAKKUNG)** 4일차. 어제 만든 멀티에 **탈출구**를 세우고 맵을 키웠다.
> 그 과정에서 **문서와 코드가 어긋나 있던 자리**가 여럿 드러나 같이 정리했다.

## 오늘의 결론부터

> **어긋남은 게으름이 아니라 구조 문제다.**
> 같은 사실을 두 군데 적으면 한 군데는 반드시 낡는다. 오늘 고친 것 대부분이
> "값이 두 곳에 있어서" 또는 "확인용으로 둔 값이 확인을 막아서" 생긴 것이었다.

| 한 것 | |
|---|---|
| 커밋 | 어제 미커밋분을 2개로 나눠 커밋 → 오늘 것까지 **3개 푸시** |
| 맵 | 19×19 → **33×33** (통로 169→530칸, 최단 주파 20→41초) |
| 탈출구 | 서버에만 있고 화면엔 없던 문을 **실제로 세움** |
| 솔로 | 손으로 적은 7×7 제거 → 서버와 **같은 생성기**를 부른다 |
| 문서 | `docs/기술스택.md` 신설 · 기획서 §5 축소 · README 정정 |

검증: typecheck 0 · 규칙 370 · 소켓 47 · 미니맵 13 · 빌드 성공.

## 공부한 것

### 1. 정보 은닉에는 세 번째 방식이 있다 — "보일 때만 준다"

탈출구가 **서버에만 있고 화면에는 없었다.** 심장박동이 빨라지다 갑자기 `탈출` 배너가
뜨는 게 전부였다. 문 앞에 서도 아무것도 안 보인다.

그런데 좌표를 주면 §4.3 ③(도망자는 탈출구 위치를 모른다)이 무너진다. 두 선택지가 다 틀렸다.

| | 결과 |
|---|---|
| 늘 준다 | 개발자 도구를 여는 순간 게임 끝 |
| 아예 안 준다 | 문을 그릴 수 없다 |
| **보일 때만 준다** | 사람에게 이미 쓰던 규칙(정면 4칸·벽 없음)을 그대로 태운다 |

```ts
const e = los.find(c => c.x === g.exit.x && c.y === g.exit.y);
if(e) view.exitSeen = { x:e.x, y:e.y, d:e.d };
```

이미 있는 규칙을 재사용했더니 새 규칙이 필요 없었다. 상대 플레이어를 거르는 `lineOfSight`
배열을 그대로 한 번 더 훑는 게 전부다.

교훈: **"보여줄까 말까"는 이진 선택이 아니다.** 조건을 붙이면 세 번째 답이 나오고,
그 조건은 대개 **이미 다른 곳에서 쓰고 있는 것**이다.

### 2. 같은 재료가 한 곳에서는 틀리고 한 곳에서는 맞다

문을 그릴 때 `MeshBasicMaterial`(스스로 빛나는 재질)을 썼다.
그런데 **그것의 얼굴에서는 이게 명시적으로 틀린 선택**이었다 — 어둠 속에서 얼굴이 빛나면
"손전등이 비출 때만 드러난다"는 연출이 통째로 무너지기 때문이다.

탈출구는 반대다. 안개 너머로 **빛이 먼저 오고**, 그게 심장박동이 말하던 것의 답이어야 한다.

> 재질 선택에 옳고 그름이 없었다. **무엇을 숨기고 무엇을 드러낼 것인가**가 정했다.

교훈: 기술적 판단을 "이 상황에서는 X를 쓴다"로 외우면 틀린다. 같은 프로젝트 안에서도
의도가 반대면 답이 반대다.

### 3. 도구가 값을 조용히 고치면, 값과 실제가 어긋난다

"맵 32×32로 늘리자"를 받고 코드를 보니 생성기가 이렇게 돼 있었다.

```ts
w = w % 2 ? w : w + 1;   // 벽/통로가 교대하려면 홀수여야 한다
```

**32를 넣어도 실제로는 33이 나온다.** 설정에 32라고 적고 실제는 33인 상태가 되는 것이다.
값 자체를 33으로 적고, 홀수인지 확인하는 테스트를 넣었다.

교훈: 입력을 보정하는 함수가 있으면 **설정값이 거짓말을 하기 시작한다.**
보정을 없앨 수 없으면 **보정이 필요 없는 값을 쓰고, 그걸 검사**해야 한다.

### 4. "확인용" 하드코딩이 확인을 막았다

맵을 33×33으로 키우고 문까지 세운 뒤 "5200에서 보라"고 안내했는데,
**보이는 건 작은 미로와 아무것도 아니었다.**

원인: 솔로 미로가 `src/core/space.ts` 에 손으로 적힌 **7×7 문자열**이었다.
33×33은 서버 기본값이라 접속해야만 적용된다.

```ts
const SOLO_GRID = ['#######', '#.....#', ...];   // 이게 진짜를 가리고 있었다
```

고친 방식이 중요하다. 값을 33×33으로 바꾼 게 아니라 **하드코딩을 지웠다.**

```ts
const SOLO = generate(MAZE_W, MAZE_H, seed);
const spawn = placeSpawns(SOLO.grid, seed, 1);
```

`server/maze.ts` 는 네트워크도 타이머도 모르는 순수 함수라 **클라이언트에서 그냥 부르면 된다.**
어제 "전송 계층을 갈아엎어도 안 고쳐진다"고 적었던 그 성질이, 오늘은 **계층을 건너뛴 재사용**으로 쓰였다.

교훈: 개발 편의로 둔 가짜 데이터는 **진짜를 확인해야 할 때 정확히 방해가 된다.**
"어차피 연습용"이라고 둔 값이 검증을 막았다.

### 5. 두 군데 적힌 값은 한 곳이 반드시 낡는다

맵 크기가 서버(`rules.ts`)와 솔로 양쪽에 필요해졌다. 두 곳에 33을 적을 뻔했다.
`shared/protocol.ts` 에 `MAZE_W/MAZE_H` 하나를 두고 양쪽이 그걸 본다.

같은 병이 문서에도 있었다. 기획서 §5(기술 스택)를 읽어보니 **네 항목이 사실이 아니었다.**

| 적혀 있던 것 | 실제 |
|---|---|
| UI/HUD **React** | 안 쓴다. 프레임워크 없는 DOM |
| 멀티플레이 **`ws`** | Colyseus — 어제 뒤집혔는데 문서가 안 따라왔다 |
| 얼굴 텍스처 `VideoTexture` | `CanvasTexture` |
| 배포 정적 호스팅(Vercel) | 권위 서버라 불가 |

그리고 **TypeScript가 표에 아예 없었다.** 언어를 통째로 바꿨는데 스택 표에 없다.

해결도 같은 원리로 했다. `docs/기술스택.md` 하나를 만들고 **기획서에서는 표를 지우고 링크만** 남겼다.
기획서에는 "왜 웹인가 / 왜 Unity가 아닌가"만 남는다 — 그건 안 낡는 내용이다.

> **낡는 것과 안 낡는 것을 갈라서 다른 파일에 둔다.**

### 6. 문서를 쓰다가 코드의 거짓말을 찾았다

스택 문서에 "Node 24 필요"라고 적으려다 `package.json` 을 봤다.

```json
"engines": { "node": ">=18" }
```

**거짓이다.** 서버는 Node 의 타입 스트리핑(`node serve.ts`)에 의존하는데 그건 22.18/23.6부터다.
Node 20인 팀원이 `git pull && npm install && npm start` 하면 **이유 모를 문법 오류**를 본다.

교훈: 문서화는 기록 작업이 아니라 **점검 작업**이다. "무엇을 쓰는지 적는다"를 하려면
실제로 뭘 쓰는지 확인해야 하고, 그때 어긋남이 드러난다.

### 7. "아직 필요 없다"와 "있으면 안 된다"는 다르다

DB가 필요한지 물음을 받고 정리하다 보니, 답이 하나가 아니었다.

| 데이터 | 왜 저장 안 하나 |
|---|---|
| 판 상태 · 방 코드 · 이름 · 재접속 토큰 | **아직 필요 없다** — 상황이 바뀌면 넣을 수 있다 |
| **얼굴 스냅샷** | **있으면 안 된다** — 생체인식정보. DB에 들어가는 순간 §7이 무너진다 |

이걸 안 갈라두면 나중에 "DB 붙이는 김에 얼굴도" 가 된다.
그래서 문서에 **"나중에 DB를 붙이더라도 얼굴만은 예외로 남는다"** 를 명시했다.

교훈: 같은 결론("지금 안 한다")도 **이유가 다르면 유효기간이 다르다.**
이유를 안 적으면 나중에 잘못 뒤집힌다.

### 8. 검증할 수 없는 것은 코드가 아니라 문서에 남긴다

Redis를 붙일까 하다가 멈췄다. 로컬에 Redis가 없으니 **한 번도 실행되지 않은 경로**가 생긴다.
금요일에 워커로 정확히 그 실수를 했었다(검증 안 된 경로를 기본값으로).

그래서 코드는 안 건드리고 문서에 **붙이는 법 + 붙일 때 확인할 것**을 적었다.

- 프로세스 2개로 **방 목록이 공유되는지** 확인 전에는 배포하지 않는다
- 로드밸런서가 좌석 예약을 맞는 프로세스로 보내는지 (`consumeSeatReservation` 이 여기서 터진다)
- 얼굴은 Redis에 넣지 않는다

그리고 **왜 안 붙였는지**도 문서에 한 줄 남겼다. 안 적으면 나중에 "왜 안 했지"가 된다.

교훈: 지난주의 교훈을 **실제로 적용한 첫 사례**다. 원칙은 적어둘 때가 아니라
"지금 하면 편한데" 싶을 때 지키는지로 판가름 난다.

### 9. 커밋을 나누는 기준은 파일이 아니라 헹크다

어제 미커밋분을 둘로 나눴다. 파일이 안 겹쳐서 깔끔했다.

- `maxPayload` 버그 → `serve.ts` · `nettest.ts`
- 모듈 분할 → `src/` · `test/` · tsconfig

반면 오늘 것(맵 크기 + 탈출구 + 솔로 미로)은 **하나로 묶었다.**
`protocol.ts` 는 상수와 타입, `rules.ts` 는 DEFAULTS와 `viewFor`, `scene.ts` 는 주석과 문 —
**같은 파일의 다른 위치**를 건드려서 파일 단위로는 안 갈라진다.

교훈: "커밋은 작게"가 항상 가능한 게 아니다. 갈라지는지는 **변경이 파일 경계와
맞아떨어지는가**가 정하고, 그건 애초에 코드를 어떻게 나눠뒀는지에 달려 있다.

   문의 발광 세기(0.82)·램프 밝기(2.6)는 계산도 아니고 그냥 감이다

5. **`strict: false`** 아직 안 걷었다
