# 아이디어 정리

## 후보를 비교한 기준

이번 주에 나온 아이디어를 한곳에 모아 비교했다. 처음에는 재미있거나 신기한 아이디어를 많이 만드는 데 집중했지만, 조사와 구체화를 반복하면서 평가 기준이 점차 명확해졌다.

| 평가 기준 | 확인한 내용 |
| --- | --- |
| 사용자 문제 | 실제로 해결할 필요가 있는 불편인가 |
| AI 필요성 | AI를 제거하면 핵심 경험이 달라지는가 |
| 차별성 | 기존 서비스와 구분되는 경험이 있는가 |
| 데이터 | 학습과 검증에 필요한 자료를 구할 수 있는가 |
| 구현 범위 | 프로젝트 기간 안에 MVP를 완성할 수 있는가 |
| 역할 분배 | 프론트엔드·백엔드·AI 역할이 충분한가 |
| 시연 가능성 | 핵심 흐름을 발표에서 직관적으로 보여줄 수 있는가 |

## 이번 주에 나온 주요 방향

이번 주에는 영상 분석, 체험형 안전교육, 소개팅 훈련, 스포츠 광고 분석, AI 교육, 보이스피싱 예방, 정책 시뮬레이션, 2D 멀티플레이 게임 등 다양한 아이디어를 검토했다.

분야는 서로 달랐지만 구체화할 가치가 있는 아이디어에는 공통적인 흐름이 있었다.

```text
사용자의 선택이나 행동
          ↓
AI와 시스템의 분석
          ↓
결과와 원인에 대한 피드백
          ↓
다음 상황이나 훈련에 반영
          ↓
다시 체험하며 변화 확인
```

체험형 안전교육에서는 자세 분석 결과가 다음 훈련으로 이어진다. 소개팅 연습에서는 사용자의 약점이 다음 AI 상대에게 반영된다. AI 사건 해결 게임에서는 진단 후 같은 사건을 다시 실험하며, 보이스피싱 게임에서는 과거의 행동이 이후 공격과 방어 방법을 바꾼다.

## 생각의 변화

처음에는 “어떤 AI 기술을 사용할 수 있을까?”를 중심으로 생각했다. 하지만 여러 아이디어를 조사하고 비교한 후에는 다음 질문을 더 중요하게 보게 되었다.

> 이 서비스는 누구에게 필요한가?  
> 사용자는 AI의 분석 결과로 무엇을 할 수 있는가?  
> 기존 서비스와 어떤 경험이 다른가?  
> 프로젝트 기간 안에 핵심 기능을 보여줄 수 있는가?

아이디어는 많이 내는 것만으로 완성되지 않았다. 기존 사례를 조사하고 차별점을 확인하며, 데이터와 구현 범위를 검토하는 과정이 함께 필요했다.

## 이번 주를 돌아보며

이번 주에는 하나의 주제를 바로 선택하기보다 여러 분야의 아이디어를 넓게 탐색하고, 사용자 문제와 AI의 역할을 기준으로 후보를 좁혀 나갔다.

이 과정을 통해 좋은 프로젝트 아이디어는 최신 AI 기술을 많이 사용하는 아이디어가 아니라, **사용자 문제와 AI의 역할이 명확하고 핵심 경험을 짧게 설명할 수 있는 아이디어**라는 점을 배웠다.

다음 단계에서는 팀이 선택한 후보의 핵심 사용자와 문제 상황을 더 명확하게 정의하고, 반드시 구현해야 할 MVP 기능만 남겨 실제 프로젝트 계획으로 발전시킬 예정이다.
