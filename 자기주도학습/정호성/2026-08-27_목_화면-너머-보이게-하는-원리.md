## 오늘의 목표

조사만 하다 끝나면 안 되므로 직접 만들어본다.

**웹캠으로 눈 위치를 추적해서, 화면에 실제로 구멍이 뚫린 것처럼 보이게 하는 데모.**
고개를 왼쪽으로 옮기면 화면 안쪽의 오른편이 보이고, 다가가면 안이 넓어진다.
장비 없이 웹캠 하나로 만드는 데스크톱 VR이다.

프로젝트명 `headtrack-demo`. 레퍼런스는 Johnny Lee의 Wii 헤드트래킹(2007)과
TheParallaxView다.

이 문서는 **원리와 구조**를 정리한다. 떨림을 잡느라 고생한 내용은 ②에 따로 적었다.

### 왜 이것을 했나

내 파트가 Spatial AI인데, 결국 핵심은 **카메라로 본 것을 3D 공간 좌표로 바꾸는 것**이다.
NEXTSPOT의 영상→지도 매핑과 이 데모의 눈→월드좌표 매핑은 같은 문제다.
작은 것으로 먼저 감을 잡으려고 시작했다.

궁극적으로는 이것을 복싱 게임으로 키우고 싶어서, 그 1단계 공간감 검증이기도 하다.

## 공부한 것

### 1. off-axis projection — 오늘의 핵심 개념

보통 3D는 **카메라를 움직여서** 시점을 바꾼다.
그런데 그렇게 하면 "카메라가 돌아다니는 화면"이지 "창문 너머"가 되지 않는다.

창문처럼 보이게 하려면 반대로 해야 한다.

```
화면 = 고정된 창틀 (z=0 평면의 사각형)
눈   = 창틀 밖에서 움직이는 관찰자
```

카메라는 **항상 화면과 평행**하게 두고(회전 0), 절두체(frustum)만 눈 위치에 맞춰
비대칭으로 기울인다. 실제 코드는 이렇다.

```js
camera.position.set(hx, hy, hz);
camera.rotation.set(0, 0, 0);   // 절대 회전시키지 않는다
const s = near / hz;
camera.projectionMatrix.makePerspective(
  (-HALF_W - hx) * s,  // left
  ( HALF_W - hx) * s,  // right
  ( halfH  - hy) * s,  // top
  (-halfH  - hy) * s,  // bottom
  near, far
);
```

눈이 오른쪽으로 가면 left/right가 함께 밀려서 절두체가 찌그러진다.
이 찌그러짐이 곧 원근 착시다.

**카메라를 회전시키면 이 효과가 나오지 않는다.** 회전은 창틀까지 같이 돌려버리기 때문이다.
"카메라를 움직인다"와 "절두체를 기울인다"가 서로 다른 것이라는 점이
오늘 가장 크게 이해한 부분이다.

### 2. 눈 위치를 mm로 복원하기

MediaPipe FaceLandmarker에서 홍채 랜드마크(468~477)를 받는다.
그런데 이것은 정규화된 화면 좌표일 뿐이라, 절두체에 넣으려면 실제 mm로 바꿔야 한다.

핵심 트릭은 **IPD를 자로 쓰는 것**이다.
성인 평균 동공 간 거리는 63mm로 거의 일정하다.
그러면 화면에서 두 눈 사이가 몇 px인지만 재도 거리를 역산할 수 있다.

```
화면 속 동공간거리가 크다 = 가까이 있다
화면 속 동공간거리가 작다 = 멀리 있다
```

좌우 위치는 이렇게 나온다.

```
x = -(cx - vw/2) × IPD / eyeDistPx
```

이 식의 좋은 점은 **초점거리가 들어가지 않는다는 것**이다.
`IPD / eyeDistPx`가 곧 "px당 mm"이므로 **웹캠 화각을 몰라도 x, y는 정확하다.**
화각이 필요한 것은 z뿐이고, 그것은 표준 웹캠 66° 가정으로 처리했다.

### 3. 손 트래킹도 같은 원리로 붙였다

HandLandmarker로 양손 21관절을 추가했다.
얼굴과 **같은 비디오 스트림, 같은 wasm 런타임**을 공유한다.

거리 추정 방식도 동일하다. IPD 대신 **손바닥 길이(손목→중지 뿌리) 평균 80mm**를 자로 쓴다.
"크기를 아는 물체를 자로 삼는다"는 발상이 그대로 재사용됐다.

메인 스레드가 감당하지 못해서 **손은 2프레임에 1회만** 추론하도록 나눴다(`skip = 2`).
얼굴은 매 프레임, 손은 격프레임이다. 손은 조금 늦어도 티가 나지 않아 괜찮았다.

### 4. HTTPS가 없으면 카메라를 못 쓴다

맥북에서 테스트하려는데 카메라 권한이 떨어지지 않았다.

`getUserMedia`는 **보안 컨텍스트(localhost 또는 HTTPS)에서만** 동작한다.
LAN IP 접속은 http라서 차단된다.

| 방법 | 결과 |
| --- | --- |
| `http://<LAN IP>:5179` | 카메라 차단 |
| 자체 서명 인증서 + https | 되지만 매번 경고를 뚫어야 하고, IP가 바뀌면 재발급 |
| **tailscale serve** | 정식 인증서가 붙어 한 번에 해결 |

tailscale로 도메인을 받아서 붙이니 다른 기기에서 링크만 열면 바로 동작했다.
앞으로 계속 쓸 것 같다.

## 막힌 것 / 의문

1. **화면 물리 크기를 아직 추측으로 처리하고 있다.**
   macOS는 레티나 논리 밀도(127/109ppi)로 계산하지만, 윈도우는 dpr과 해상도로
   패널 종류를 추정하는 중이다. 이것이 틀리면 원근이 통째로 틀어진다.

2. **웹캠 화각 66° 가정.** z 추정이 여기 걸려 있는데 기기마다 다를 것이다.
   런타임에 알아낼 방법이 있는가.

3. 손 트래킹 `skip=2`가 지금은 괜찮지만 주먹처럼 빠른 동작에서도 버틸지 의문이다.
   버티지 못하면 워커로 빼야 한다.
