# 학습 일지 — 2026-08-26 (수) ②

## 오늘의 목표

"중계 영상에서 스폰서 노출을 실시간으로 분석하는 서비스"를 예전 해커톤에서 본 기억이 있다.
그것이 무엇이었는지 찾아서, 오명헌 님이 잡은 BALLBOARD(광고판 노출을 금액으로 환산)가
**이미 누가 어디까지 해놓은 문제인지** 확인한다.

---

## 찾으려던 것

기억나는 화면은 이랬다.

```
┌────────────────┬──────────────────┐
│                │  스폰서 A  ▓▓▓▓  │
│  중계 영상     │  스폰서 B  ▓▓    │  ← 영상이 재생되는 동안
│                │  스폰서 C  ▓▓▓   │     실시간으로 막대가 움직인다
└────────────────┴──────────────────┘
```

올해 구글 클라우드 스터디잼 해커톤(2026-07-16)의 스포츠 B2B 트랙 1등으로 기억한다.

---

## 조사가 깨진 이유

오늘 진짜 배운 부분은 여기다. **단서 세 개가 전부 불확실했다.**

| 단서 | 확실도 |
| --- | --- |
| 날짜 (7/16) | 낮음. "그 무렵" 수준 |
| 트랙 (스포츠 B2B) | 낮음. 트랙 표기가 아예 없는 행사였다 |
| 작성자 (한국인 개인) | 중간 |

검색은 **확실한 축이 하나라도 있어야** 좁혀진다.
셋 다 흐리면 후보가 기하급수로 늘어나 아무리 돌려도 끝나지 않는다.
실제로 몇 시간을 썼는데 남은 결과는 "못 찾음"뿐이었다.

다음부터는 조사를 시작하기 전에 "이 중 무엇이 확실한가"를 먼저 확인하고,
확실한 축이 하나도 없으면 조사를 접거나 접근 자체를 바꿔야 한다.

---

## 곁다리로 배운 것 — GitHub API rate limit

한참 돌리다 응답이 전부 비어서 확인해보니 이랬다.

```json
{ "rate": { "limit": 60, "remaining": 0, "used": 60 } }
```

**비인증 GitHub API는 시간당 60회**다. code search는 별도로 또 60회다.
이런 광범위 탐색을 하려면 토큰을 붙여야 한다 (인증 시 5,000회).

함정은 **에러가 아니라 빈 결과로 돌아온다는 점**이다.
"결과가 없다"와 "내가 차단당했다"가 겉보기에 똑같다.
앞으로 탐색이 이상하게 조용해지면 rate limit부터 확인해야겠다.

## 오늘의 결론

- 찾지 못했지만 BALLBOARD 방향이 죽은 것은 아니다.
  공개 구현이 보이지 않는다는 것은 아직 자리가 비어 있다는 쪽으로 읽을 수도 있다.
  다만 **못 찾은 것과 없는 것은 다르다.**
- 시간 대비 산출은 이번 주 최악이었다. 불확실한 기억을 쫓느라 반나절을 날렸다.

## 막힌 것 / 의문

1. "본 것 같은데"를 근거로 조사를 시작하는 것이 맞는가.
   기억의 신뢰도를 먼저 재는 방법이 있는가.

   아니면 B2B라 공개하지 않는 것인가.
3. 우리가 BALLBOARD를 한다면 "실시간"이 정말 필요한 요구사항인가.
   기존 서비스가 전부 사후 리포트라면 이유가 있을 텐데, 그 이유부터 확인해야겠다.
