영상 AI 아이디어를 더 발산하되, **무엇을 기준으로 버릴지를 먼저 정하고** 시작한다.

## 1부. 버리는 기준부터 정했다

### 왜 기준이 먼저인가

어제 NEXTSPOT을 정리하면서 느낀 것이 있다.
아이디어는 정리하면 할수록 그럴듯해진다. 표를 그리고 기능을 나열하면
전부 될 것처럼 보인다.

그러면 나중에 후보가 5개, 10개가 됐을 때 하나도 못 버린다.
**판단 기준이 아이디어보다 먼저 있어야 한다.**

### 기준 ① — 루프가 닫히는가

지난 프로젝트 회고에서 얻은 것이 있다.
발표에서 가장 반응이 좋았던 부분은 기능 설명이 아니라
"쿠팡 링크를 눌러서 실제로 60원을 벌었다"는 한 문장이었다.

기술적으로는 60원이 아무 의미가 없다. 그런데도 그것이 통했다.
왜 통했는지 뜯어보면 **루프가 실제로 닫혔기 때문**이다.

```
사용자가 행동한다 → 시스템이 반응한다 → 결과가 숫자로 돌아온다 → 다시 행동한다
```

이 고리가 한 바퀴라도 실제로 돌면 데모가 살아난다.
돌지 않으면 아무리 기술이 좋아도 "그래서 이걸 왜 쓰는가"에 답할 수 없다.

기능이 아무리 많아도 **한 방향 파이프라인이면 루프가 아니다.**
결과가 사용자에게 돌아와서 다음 행동을 바꿔야 루프다.

### 기준 ② — 분석인가 생성인가

특화 주제가 "AI 영상"인데, 여기에는 두 갈래가 있다.

| | 생성 | 분석 |
| --- | --- | --- |
| 하는 일 | 프롬프트 → 이미지·영상을 만든다 | 영상 → 무엇인가를 알아낸다 |
| 우리가 만드는 것 | API 호출과 UI | 검출·추정·예측 파이프라인 |
| 모델을 바꾸면 | 서비스가 통째로 바뀐다 | 부품 하나가 바뀐다 |
| 경쟁 상대 | 모델을 만드는 회사 | 같은 문제를 푸는 팀 |

**생성 쪽으로 가면 우리가 만든 것이 남지 않는다.**
모델 회사가 다음 버전을 내면 우리 서비스의 가치가 그쪽으로 흡수된다.

그래서 기준을 "영상을 **분석**하는 쪽이어야 한다"로 잡았다.

## 2부. 아이디어 A — 콘서트 멀티앵글 아카이브

**한 줄 정의:** 내가 콘서트에서 찍은 영상을 올리면, 같은 시각에 다른 사람이 찍은
영상을 자동으로 찾아 붙여주는 팬 커뮤니티.

### 문제 정의

콘서트 직캠은 원래 이런 식으로 소비된다.

> "그 부분 다른 각도로 본 사람 없나"

그런데 지금은 유튜브에서 제목으로 검색하는 것이 전부다.
제목이 부정확하거나 표기가 다르면 찾지 못한다.
같은 공연, 같은 순간의 영상이 수십 개 올라와 있어도 서로 연결되지 않는다.

여기서 진짜 문제는 **"같은 순간"을 어떻게 판정하는가**이고, 이것이 영상 AI 문제다.

### 정렬 방법 후보 세 가지

**(1) 파일 타임스탬프**

EXIF나 파일 생성 시각을 쓰는 방법. 가장 간단하지만 **폰 시계가 제각각**이다.
수 초에서 수 분까지 어긋나고, 편집·업로드를 거치면 메타데이터가 날아가기도 한다.
콘서트 한 곡이 3~4분인데 오차가 분 단위면 쓸 수 없다.

**(2) 오디오 지문**

같은 공연장 안이라면 **소리는 하나**다.
각도가 달라도 모두 같은 음원을 녹음하고 있는 셈이다.

Shazam 방식(스펙트로그램의 피크를 뽑아 해시로 만드는 것)을 곡 검색이 아니라
**같은 녹음 사이의 시간 오프셋 추정**에 쓰는 것이다.

```
영상 A의 오디오 ─┐
                 ├→ 지문 추출 → 해시 매칭 → 오프셋 t초 → 정렬
영상 B의 오디오 ─┘
```

우려되는 부분은 열화다. 관객석에서 폰으로 녹음한 소리는 함성, 위치별 거리 차이,
폰 마이크의 자동 게인 조정 때문에 원음과 상당히 다르다.
그래도 **같은 함성이 같은 시각에 들어간다는 점**은 오히려 정렬에 유리할 수도 있다.

**(3) 영상 밝기 시계열**

무대 조명이 바뀌는 시점, 연출 전환 시점을 맞추는 방법.
각도가 다르면 화면이 완전히 달라지므로 프레임 자체는 비교할 수 없지만,
**밝기 변화의 시계열**만 뽑아서 맞추는 식이라면 가능성이 있다.

| 방법 | 원리 | 판단 |
| --- | --- | --- |
| 파일 타임스탬프 | 메타데이터 | 오차가 분 단위라 부적합 |
| **오디오 지문** | 같은 공연장 = 같은 소리 | 주 경로로 채택 |
| 영상 밝기 시계열 | 조명 전환 시점 매칭 | 보조 수단 |

### 기준 적용

| 기준 | 판정 |
| --- | --- |
| 루프가 닫히는가 | 통과 |
| 분석인가 | 통과. 오디오·영상을 분석해 관계를 알아내는 것이다 |

루프가 특히 잘 닫힌다.

```
내가 올린다 → 남의 각도가 붙는다 → 내 영상도 남에게 붙어 노출이 는다 → 또 올린다
```

기여할수록 이득이 커지는 구조라 초기 사용자 유입 설계까지 명확하다.

### 걸리는 것

**저작권**이 가장 크다. 콘서트 촬영물 자체가 회색지대인데,
그것을 모아서 서비스로 만들면 정면으로 부딪친다.
지금 팬 커뮤니티나 유튜브 직캠이 방치되고 있는 것은
**단속하지 않는 것이지 허용된 것이 아니다.**
개인이 올리는 것과 플랫폼이 모아서 제공하는 것은 법적 위치가 다르다.

그 외에 콜드스타트(같은 공연에 최소 2명이 올려야 성립),
6주 범위(지문·커뮤니티·플레이어를 전부 만들어야 함)가 걸린다.

### 판정

**보류.** 아이디어 자체는 이번 주에 나온 것 중 가장 재미있지만
법적 리스크가 커서 주제로 밀기는 어렵다.

다만 기술만 떼어내는 길이 있다.
**"같은 시각에 찍힌 영상을 자동 정렬한다"**는 부분은 저작권과 무관하게 쓸 수 있다.
행사 영상, 스포츠 다각도 촬영, 사고 현장의 여러 목격자 영상에도 적용된다.

## 3부. 아이디어 B — 그림일기 (오늘 나온 것 중 가장 나쁘다)

**한 줄 정의:** 하루를 적으면 AI가 그림일기로 그려주는 서비스.

기준을 세우자마자 바로 걸러진 것이다.
왜 나쁜지 정리해두는 것이 오늘 가장 남는 부분이다.

| 기준 | 판정 |
| --- | --- |
| 루프가 닫히는가 | 닫히지 않는다 |
| 분석인가 | 생성이다 |

### 루프가 닫히지 않는다

```
일기를 쓴다 → 그림이 나온다 → 끝
```

그림이 나온 다음에 사용자가 할 일이 없다.
시스템도 사용자로부터 아무것도 배우지 않는다. 다음 일기가 더 나아지지도 않는다.
한 방향 파이프라인이지 루프가 아니다.

### 생성이지 분석이 아니다

프롬프트를 넣고 이미지 API를 호출하는 것이 전부다. 우리가 만든 것이 없다.
모델을 갈아끼우면 그대로 끝난다.

### 이미 널려 있다

일기 앱과 이미지 생성의 조합은 난이도가 사실상 0이라 이미 수십 개가 나와 있다.
차별점을 만들려면 그림 품질로 싸워야 하는데, 그것은 모델 회사를 이겨야 한다는 뜻이다.

### 판정

**탈락.** 다만 버린 이유가 명확해서 좋은 반례로 남는다.
앞으로 아이디어가 나올 때마다 **"이건 그림일기 아닌가"**를 물어보면 된다.

## 배운 것

**아이디어를 늘리는 것보다 버리는 기준을 먼저 잡는 것이 빠르다.**
기준 없이 발산하면 전부 그럴듯해 보여서 아무것도 못 버린다.
기준 두 개를 세우자 그림일기는 3초 만에 걸러졌다.

**같은 아이디어라도 "무엇을 서비스로 파느냐"에 따라 리스크가 완전히 달라진다.**
콘텐츠를 모아서 파는 순간 저작권 문제가 되지만, 정렬 기술만 파는 것은 문제가 되지 않는다.
아이디어를 버리기 전에 **떼어낼 수 있는 부분이 있는지** 먼저 봐야겠다.

그리고 **"기술적으로 되는가"보다 "이미 있는가"를 먼저 봐야 한다.**
되는지 조사하는 데 반나절을 쓰고 나서 이미 있는 서비스임을 알면 반나절이 통째로 날아간다.

## 막힌 것 / 의문

1. 오디오 지문으로 **함성이 섞인 아마추어 녹음** 사이의 정렬이 실제로 되는가.
   원곡 대조가 아니라 열화된 녹음끼리의 대조라 난이도가 다를 것이다.
   짧은 샘플 두 개로 먼저 실험해볼 필요가 있다.
2. 콘서트 영상 저작권의 실제 경계가 어디인가. 지금의 팬 커뮤니티는 왜 방치되고 있는가.
3. 기준 두 개로 충분한가. "6주 안에 되는가"가 빠져 있는데,
   이건 아이디어 단계에서는 판단이 어려워서 일단 뺐다.
4. NEXTSPOT을 포함해 후보가 늘었는데 최종 하나를 무엇으로 고를 것인가.
   결국 **6주 안에 끝나는가**가 마지막 기준이 될 것 같다.
