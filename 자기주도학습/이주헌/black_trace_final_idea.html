01 / CONCEPT

이 프로젝트가 정확히 무엇인가

Unity나 Unreal로 만드는 정교한 액션 게임이 아니다. 흰색 길과 검은색 벽, 원형 캐릭터, 제한된 시야만으로 성립하는 짧은 웹 게임이다.

술래가 제한된 블록과 가짜 출구를 준비하고, 탈출자들은 직접 걸어 다니며 각자의 지도를 완성해 진짜 출구를 찾는다. 경기 종료 후에야 전체 미로와 모든 사건이 공개된다.
핵심 경험

정보를 모으는 추격전

빠른 조작보다 “내가 아는 길”, “상대가 알 것 같은 길”, “소리가 발생한 방향”을 조합하는 판단이 중심이다.

플레이 범위

단순한 칸 단위 이동

WASD 또는 방향키로 한 칸씩 이동한다. 충돌, 시야, 출구 판정 모두 격자 좌표로 처리한다.

AI의 위치

게임 밖에서 강하게

AI는 승패를 판단하지 않는다. 정확한 서버 로그를 바탕으로 주요 장면을 고르고 짧은 2D 영상을 만든다.

02 / ROLES

같은 미로를 보지만, 저장되는 정보가 다르다

이 프로젝트의 가장 중요한 차별점이다. 단순히 능력치가 다른 것이 아니라, 두 진영이 기억하는 세계 자체가 다르다.

R

탈출자

RUNNER · 탐색과 협동

현재 주변을 보며 이동하고, 직접 확인한 길과 벽은 개인 지도에 계속 남는다. 팀원과 만나야 서로의 지도 정보가 합쳐진다.

  • 방문한 통로와 발견한 벽을 영구 기록
  • 아직 탐색하지 않은 영역은 안개 처리
  • 팀원과 인접하면 지도 일부 동기화
  • 소리 미끼 또는 팀 공용 벽 파괴권 사용
  • 장치 2개를 활성화해 진짜 출구 개방
H

술래

HUNTER · 기억과 추론

현재 주변은 볼 수 있지만 일반 경로는 지도에 남지 않는다. 준비 단계에서 자신이 설치한 벽·가짜 출구·센서만 영구 표식으로 보인다.

  • 경기 전 제한된 구역에 검은 블록 배치
  • 자신이 설치한 구조물을 랜드마크로 활용
  • 센서와 발소리로 대략적인 방향 추적
  • 전체 지도와 진짜 출구 위치는 알 수 없음
  • 기억과 설치물 배치를 이용해 동선 예측
INTERACTIVE MOCKUP

역할별로 지도가 어떻게 달라지는가

버튼을 눌러 같은 순간을 탈출자, 술래, 전체 진실의 관점으로 비교할 수 있다.

03 / GAME FLOW

한 판은 준비 45초, 추격 4분으로 끝난다

탐색만 하다 끝나거나 우연히 출구를 바로 찾는 문제를 막기 위해, 출구를 열기 위한 공동 목표를 둔다.

STEP 01기본 미로 생성순환 통로가 포함된 64×64 맵과 진짜 출구를 서버가 생성한다.
STEP 02술래 준비일부 건설 구역에서 제한된 블록·가짜 출구·센서를 배치한다.
STEP 03조건부 랜덤 배치출구·상대와 일정 거리 이상 떨어진 위치에서 모두 시작한다.
STEP 04개인 탐색탈출자는 지도를 만들고, 술래는 소리와 자기 설치물을 따라 움직인다.
STEP 05장치 활성화탈출자 팀이 맵 안의 장치 2개를 찾아 작동시킨다.
STEP 06최종 추격진짜 출구가 열리며 술래에게도 대략적인 출구 방향이 알려진다.
STEP 07진실 공개전체 맵·이동 경로·엇갈린 순간을 공개하고 AI 영상을 만든다.
항목권장값설계 이유
논리 맵64 × 64브라우저 렌더링과 조우 밀도의 균형. 화면에서는 칸을 확대해 큰 픽셀판처럼 표현한다.
인원술래 1명 : 탈출자 3명웹 프로젝트에서 매칭과 실시간 동기화 범위를 통제하면서도 협동이 성립한다.
준비 시간45초설치 전략은 주되, 실제 플레이보다 준비가 길어지는 것을 방지한다.
추격 시간4분간단히 접속해 즐길 수 있는 짧은 라운드 구조를 유지한다.
술래 예산벽 18칸 · 가짜 출구 1개 · 센서 2개무제한 봉쇄를 막고 배치 선택에 의미를 준다.
탈출 조건장치 2개 → 출구 개방 → 2명 이상 탈출우연한 조기 탈출을 방지하고 중반 협동 목표를 만든다.
술래 승리2명 포획 또는 시간 종료한 명을 계속 쫓는 캠핑보다 전체 동선 통제를 유도한다.
04 / FUN

복잡한 그래픽 없이도 재미를 만드는 블록 규칙

새 기능은 모두 “칸의 상태”와 “정보 공개 방식”으로 구현한다. 3D 함정, 물리 엔진, 복잡한 캐릭터 스킬은 넣지 않는다.

?

가짜 출구

진짜 출구처럼 보이지만 2초간 상호작용하면 경보가 발생한다. 술래에게 방향을 알려주고 탈출자 지도에는 가짜로 기록된다.

S

소리 센서

탈출자가 지나가면 정확한 좌표가 아니라 방향 신호만 술래에게 전달한다. 술래가 직접 배치했기 때문에 추론이 가능하다.

↗

소리 미끼

탈출자가 다른 위치에 가짜 신호를 발생시켜 술래를 유인한다. 술래는 실제 발소리인지 미끼인지 판단해야 한다.

⇄

지도 동기화

탈출자끼리 인접했을 때만 서로의 탐색 영역이 합쳐진다. 흩어져 탐색할지 모여 정보를 합칠지 선택하게 한다.

□

팀 공용 벽 파괴

술래가 설치한 벽 한 칸을 제거할 수 있지만 큰 소리가 난다. 우회와 위치 노출 사이의 선택을 만든다.

⌁

잔향 모드

잡힌 탈출자는 관전만 하지 않고 일정 시간마다 미탐색 구역 또는 위험 방향 핑을 한 번 보낼 수 있다.

가장 중요한 설계

모든 행동은 정보를 만들거나 왜곡해야 한다

달리기, 센서 통과, 가짜 출구 조사, 벽 파괴, 지도 교환이 모두 상대에게 신호를 주거나 팀의 지식을 갱신한다. 단순 이동 시간도 의사결정이 된다.

피해야 할 설계

벽 한 칸으로 출구를 완전히 봉쇄하는 상황

술래가 블록을 놓을 때마다 서버가 BFS로 모든 필수 지점에서 출구까지 최소 한 경로가 남는지 검사하고, 조건을 깨는 배치는 거부한다.

06 / AI VIDEO

AI 영상은 “상상해서 만들기”가 아니라 “경기를 재구성하기”다

게임은 항상 정확한 2D 리플레이를 먼저 만든다. AI는 실제 로그에서 하이라이트를 고르고, 픽셀 스타일의 짧은 영상으로 연출하는 역할만 맡는다.

01 · LOG서버 이벤트 기록좌표, 이동, 센서, 가짜 출구, 포획, 탈출을 정확히 저장
02 · DETECT주요 사건 탐지벽 하나 사이 엇갈림, 미끼 유인, 종료 직전 탈출 등을 규칙으로 검출
03 · STORY장면 순서 구성도입 → 오판 → 추격 → 반전 → 결과의 15초 구조 생성
04 · RENDER정확한 2D 원본실제 맵과 좌표로 시작·종료 프레임 및 원본 클립 렌더링
05 · GENERATEAI 스타일 변환픽셀, CCTV, 먹물, 청사진 중 하나의 2D 스타일로 재해석
06 · VERIFY검증과 합성인원·역할·핵심 사건 불일치 시 원본 리플레이로 대체

09 / RISKS

예상되는 실패 지점과 방지책

재미와 기술 양쪽에서 가장 위험한 부분을 먼저 검증해야 한다.

플레이어가 서로 만나지 못함맵이 크거나 순환 경로가 너무 많으면 추격이 발생하지 않는다.64×64부터 시작하고 센서·장치·출구 개방 신호로 후반 동선을 수렴시킨다.
술래가 무작위로 걷기만 함정보가 너무 적으면 추론이 아니라 운에 의존한다.자기 설치물 영구 표시, 소리 방향, 센서 발동, 출구 개방 신호를 제공한다.
탈출자가 완전한 지도를 너무 빨리 공유한 명의 탐색이 곧 팀 전체 정보가 되면 안개가 의미를 잃는다.직접 만남 또는 송신 지점에서만 정보가 합쳐지도록 제한한다.
술래가 출구를 봉쇄설치 자유도가 게임 불가능 상태를 만들 수 있다.설치 예산, 보호 구역, BFS 도달성 검증을 함께 적용한다.
AI 영상이 실제 경기와 다름생성 모델이 인물·장면·결과를 임의로 바꿀 수 있다.정확한 2D 리플레이를 기준 원본으로 사용하고 불일치 영상은 폐기 또는 원본으로 대체한다.
AI가 API 연결로만 보임프롬프트 한 번 전송하는 구조는 프로젝트 기여가 약하다.사건 탐지, 장면 점수화, 스토리 구성, 조건 프레임 제작, 결과 검증을 자체 파이프라인으로 구현한다.
FINAL PITCH

탈출자는 길을 기억하지만,
술래는 자신이 만든 것만 기억한다.

BLACK TRACE는 흰색 길과 검은색 벽으로 구성된 미로에서 서로 다른 정보를 가진 플레이어들이 추격하는 짧은 웹 게임이다. 경기 중에는 누구도 전체 상황을 알 수 없으며, 종료 후에야 전체 맵과 모든 이동이 공개된다. AI는 이 진실을 실제 로그에 기반한 15초짜리 픽셀 영상으로 재구성한다.
