Core Loop

1

연락 수신

2

대화 선택

답변, 통화 보류, 종료, 추가 질문 중 하나를 고른다.

3

스마트폰 행동

4

상태 누적

5

Persistent State

상태는 단순 감점 수치가 아니다. 대사, 선택지, 검증 수단, 후속 사건과 엔딩을 실제로 바꾸는 게임 데이터다.

🪪

노출된 개인정보

이름, 주소, 직장, 가족관계, 주거래 은행, 생활 패턴. 이후 사칭 대사의 구체성을 높인다.

📱

기기 보안 상태

링크 접속, 앱 설치, 접근성 권한, 화면 공유, 기기 침해, 복구 여부를 단계별로 저장한다.

🧠

공격자의 지식

공격자가 무엇을 알고 있는지 별도로 추적한다. 플레이어는 그 범위를 정확히 알지 못한다.

🛡️

확보한 방어 수단

공식 연락처, 가족 확인 암호, 통화 녹음, 다른 기기, 계좌 잠금 같은 긍정적 콜백.

🏙️

정상적인 일상

실제 택배·은행·회사 연락도 섞는다. 모든 연락을 차단하면 생활상 손실이 발생한다.

나쁜 선택의 콜백

1일차에 알려준 가족 번호가 5일차 가족 사칭에 사용되고, 4일차에 허용한 접근성 권한이 6일차 공식 확인을 방해한다.

주소 노출가족 번호 노출접근성 권한 허용

좋은 선택의 콜백

2일차에 저장한 공식 번호, 3일차에 설정한 가족 암호, 4일차에 확보한 다른 기기가 마지막 공격에서 특별 선택지를 연다.

공식 채널 저장가족 암호 설정증거 확보
Campaign 01

첫 번째 캠페인: 명의도용 7일

큰 사건의 순서는 고정하되, 현재 상태에 따라 발신자 정보·대사·선택지·후속 피해가 달라지는 구조다.

DAY 01

배송 주소 확인

“고객님 택배 주소가 일부 누락됐습니다. 주소와 부재 시 연락 가능한 가족 번호를 말씀해 주세요.”

대화 선택

  • 주소와 가족 번호 제공
  • 문자로 내용을 보내달라고 요청
  • 주문 앱에서 직접 확인하겠다고 말함
  • 통화 종료

통화 중 행동

  • 쇼핑 앱 주문 내역 확인
  • 발신번호 검색
  • 가족에게 최근 주문 여부 확인
  • 통화 녹음

누적 상태

주소 노출가족 번호 노출공식 앱 검증통화 녹음

후속 콜백

주소를 제공했다면 2일차 문자와 3일차 카드사 사칭에 실제 지역 정보가 포함된다.

DAY 02

미신청 카드 배송 문자

“김민재 고객님, 서울 ○○구 배송 예정 카드가 본인 미신청 카드로 접수되었습니다.”

가능한 행동

  • 문자에 적힌 번호로 전화
  • 문자 링크 열기
  • 은행 공식 앱 열기
  • 검색광고 최상단 번호 이용
  • 문자 신고

핵심 함정

“번호를 다시 확인했다”는 행동도 출처에 따라 안전도가 다르다. 문자 속 번호, 검색광고 번호, 공식 앱 내부 번호를 구분해야 한다.

누적 상태

가짜 고객센터 접촉링크 접속공식 번호 저장

후속 콜백

가짜 고객센터에 접촉하면 3일차 발신자가 “어제 접수한 내용”을 정확히 알고 등장한다.

DAY 03

가짜 카드사 직원

“어제 미신청 카드 취소 요청하셨죠? 고객님 주소와 보호자 정보가 신청서에 등록돼 있습니다.”

새로운 요구

  • 주거래 은행 확인
  • 계좌 잔액 확인
  • 본인인증 번호 전달
  • 금융기관 담당자 연결

심리 장치

전날 사건을 정확히 언급하고 이미 노출된 정보를 읽어주며 공식 담당자라는 신뢰를 만든다.

방어 선택

  • 접수번호만 받은 뒤 통화 종료
  • 은행 공식 앱의 상담 채널 확인
  • 다른 기기에서 카드사 문의

후속 콜백

주거래 은행을 말하면 4일차 수사기관과 7일차 최종 공격이 해당 은행을 사칭한다.

DAY 04

수사기관 사칭과 보안 앱

“계좌가 범죄자금 세탁에 이용됐습니다. 피해자로 인정받으려면 보안 점검 앱을 설치해야 합니다.”

침해 단계

  • 링크 클릭 → 의심 상태
  • 앱 설치 → 위험 증가
  • 접근성 권한 → 기기 침해
  • 화면 공유 → 금융정보 노출

복구 가능성

설치했다고 즉시 게임오버가 아니다. 권한 해제, 네트워크 차단, 다른 기기에서 계좌 잠금으로 피해를 줄일 수 있다.

누적 상태

기기 침해화면 공유다른 기기 확보

후속 콜백

기기가 침해되면 5~6일차에 같은 휴대전화로 검증하는 행동의 신뢰도가 낮아진다.

DAY 05

가족 사칭 긴급 연락

“어머니 박○○님이 사고를 당하셨습니다. 휴대전화를 사용할 수 없어 병원 직원이 대신 연락드렸습니다.”

상태 기반 변화

1일차에 가족 정보를 노출했다면 실제 이름·관계가 등장한다. 노출하지 않았다면 일반적인 사칭으로 난이도가 낮아진다.

특별 선택지

  • 미리 설정한 가족 확인 암호 사용
  • 다른 가족에게 별도 연락
  • 다른 사람의 기기로 확인
  • 상대가 알려준 병원 번호로 전화

핵심 판단

기기가 이미 침해된 상태라면 같은 휴대전화로 가족에게 전화하는 것만으로는 충분하지 않다.

후속 콜백

가족에게 사전 경고를 해두었다면 공격 확산을 막고 7일차 신고 협조를 받을 수 있다.

DAY 06

실제 은행의 이상거래 연락

이번 연락은 진짜다. 하지만 진짜 직원이라는 이유로 전화에서 인증정보를 넘겨주는 것도 안전한 행동은 아니다.

단순 차단 공략 방지

모든 연락을 무시하면 실제 이상거래가 계속되거나 카드가 정지되는 생활상 손실이 발생한다.

최선의 대응

  • 통화 종료
  • 독립적인 공식 앱 확인
  • 직접 카드 잠금
  • 다른 기기에서 고객센터 문의

상황별 차이

기기가 정상이라면 공식 앱 검증이 유효하다. 기기가 침해됐다면 다른 기기를 이용해야 한다.

교육 목표

“사기범을 맞히는 능력”보다 “연락의 진위와 무관하게 안전한 확인 절차를 수행하는 습관”을 평가한다.

DAY 07

연쇄 공격의 결말과 최종 대응

공격자는 지금까지 확보한 이름·주소·가족·은행·기기 상태를 모두 활용해 마지막 송금을 압박한다.

최종 행동

  • 다른 기기에서 은행 연락
  • 계좌 지급정지
  • 기기 네트워크 차단
  • 앱 권한 해제
  • 가족 경고와 경찰 신고

상태 기반 선택지

이전에 확보한 통화 녹음, 신고 접수번호, 가족 암호, 공식 연락처에 따라 더 빠르고 강력한 대응이 열린다.

게임 종료 방식

성공·실패 한 줄이 아니라 예방, 차단, 침해 후 복구, 부분 피해, 연쇄 피해, 과잉 차단으로 결말을 세분화한다.

최종 리포트

1일차 선택부터 7일차 피해까지 공격의 인과관계를 그래프로 보여준다.

Narrative Callback

플레이어가 체감하는 공격의 연결

부재 시 연락 가능한 어머니 번호 제공

당장은 아무 피해도 발생하지 않고 통화가 자연스럽게 종료된다.

보호자 정보가 포함된 카드 배송 문자

전날 제공한 정보가 공식 시스템에 등록된 것처럼 보이기 시작한다.

카드사 직원이 어머니 이름을 정확히 언급

플레이어는 “개인정보를 알고 있으니 진짜 담당자”라고 오판하기 쉬워진다.

어머니 사고를 빌미로 한 가족 사칭

이전 정보가 권위 사칭에서 감정적 압박 수단으로 전환된다.

가족 보호를 명분으로 송금 요구

마지막 행동만 보면 갑작스러운 피해 같지만, 실제로는 1일차부터 설계된 연쇄 공격이다.

완전 예방

개인정보 노출과 기기 침해를 막고 정상 금융 문제까지 공식 채널로 해결한다.

공격 차단

일부 정보는 노출됐지만 금전 피해 전 연쇄 공격의 연결고리를 끊는다.

침해 후 복구

악성 앱이나 권한을 허용했지만 다른 기기와 계좌 잠금으로 피해를 방지한다.

AI Strategy

AI는 판정자가 아니라 표현 엔진으로 사용한다

게임의 안전성·재현성·QA를 위해 상태 변화와 정답 판정은 규칙 엔진이 담당하고, AI는 같은 상황을 자연스럽고 다양하게 표현한다.

규칙 엔진

현재 날짜, 사건 조건, 공격자 지식, 기기 상태, 보유한 방어 수단을 읽고 발생할 사건과 선택 결과를 결정한다.

→

AI 표현 계층

등장인물별 말투, 문자 문구, 상태에 맞는 개인정보 삽입, 플레이 종료 후 설명을 생성한다. 필요하면 TTS로 음성을 만든다.

→

결정론적 판정

개인정보 노출, 기기 침해, 피해 규모, 다음 사건 조건, 엔딩은 사전에 정의한 규칙으로만 계산한다.

사용자 선택 ↓ 상태 변경 규칙 적용 ├─ exposed.address = true ├─ attacker.knows_family = true └─ evidence.call_recording = false ↓ 다음 사건 조건 평가 ↓ AI에 허용된 상태 정보만 전달 ↓ 상태에 맞는 전화 대사·문자 표현 생성 ↓ 플레이어에게 다음 장면 제시

MVP Scope

넓게 만들기보다 하나의 캠페인을 깊게

6명 내외 팀 프로젝트라면 수십 개의 얕은 시나리오보다, 상태 콜백이 명확한 7일 캠페인 하나를 완성하는 편이 시연 효과와 차별성이 크다.

콘텐츠

가상 캐릭터 1명, 7일 캠페인 1개, 핵심 사건 12~15개, 정상 연락 3개 이상, 엔딩 6개.

가상 스마트폰

전화, 문자, 메신저, 은행, 브라우저, 설정 앱. 실제 휴대전화 기능과 외부 발신은 사용하지 않는다.

상태 엔진

개인정보·기기 침해·공격자 지식·방어 수단·일상 문제를 포함한 상태 15~25개.

AI 기능

상태 기반 대사 변형, 등장인물별 TTS, 문자 표현 생성, 플레이 종료 후 행동 분석 문장.

결과 화면

취약 유형 점수, 7일 타임라인, 공격 인과관계 그래프, 다른 선택을 했을 때의 대안 경로.

2회차 가치

일부 정상 연락 위치, 발신자 역할, 압박 수단, 대사 표현을 변형해 정답 암기를 방지한다.

MVP에 포함

  • 턴 기반 선택과 앱 행동
  • 이전 선택의 상태 누적
  • 잘못된 선택 이후 복구 분기
  • 정상·사기 연락 혼합
  • 최종 공격 그래프

MVP에서 제외

  • 실제 전화 발신과 실제 개인정보 입력
  • 자유 음성 대화와 무한 AI 생성
  • 복잡한 멀티플레이
  • 수십 개의 독립 캠페인
  • 3D·유니티 수준의 대형 게임 연출

Risks & Guardrails

보안 교육 게임이 지켜야 할 설계 원칙

실제 개인정보를 받지 않는다

플레이어는 미리 만들어진 가상 인물을 조작한다. 실제 이름·가족·은행 정보 입력을 요구하지 않는다.

범죄 스크립트를 과도하게 제공하지 않는다

공격자의 구체적인 실행 기술보다 피해자의 검증과 복구 행동에 초점을 둔다.

AI가 정답을 결정하지 않는다

LLM의 변동성으로 안전 수칙이 바뀌지 않도록 판정과 상태 변화는 규칙으로 고정한다.

하나의 실수로 즉시 게임오버하지 않는다

링크 클릭, 앱 설치, 권한 허용 이후에도 차단·복구·신고를 학습할 수 있도록 후속 플레이를 제공한다.

Final Pitch

보이스피싱을 맞히는 게임이 아니라,
공격자가 나를 알아가는 7일을 버티는 게임.

《끊고 확인: 7일》은 가상의 스마트폰에서 전화·문자·메신저·앱을 조작하며 연쇄 피싱 사건을 막는 선택형 보안 생존 게임이다. 플레이어가 무심코 흘린 정보와 허용한 권한은 공격자의 지식으로 누적되고, 며칠 뒤 더 정교한 사칭으로 돌아온다. 반대로 공식 연락처 저장, 가족 확인 암호, 통화 녹음, 다른 기기 확보 같은 좋은 선택 역시 마지막 위기에서 실제 방어 수단이 된다. 게임이 끝나면 단순 점수가 아니라 1일차의 작은 선택이 7일차 피해로 이어진 전체 공격 경로를 보여준다.
