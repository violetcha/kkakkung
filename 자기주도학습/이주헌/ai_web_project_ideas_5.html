현재 문제 — 출퇴근 시간 교통체증으로 시민들이 매일 평균 90분을 낭비한다.

AI 시민의 대응 — 시민들이 홀수·짝수 번호 차량을 한 대씩 구매하기 시작했다.

교통체증       -8%
등록 차량 수    +71%
가계부채       +19%
환경오염       +14%
시민 만족도     -6%

다음 패치 — 한 사람은 차량을 한 대만 소유할 수 있다.

새로운 악용 — 가족과 유령 법인을 명의자로 등록하면서 하루 동안 31만 개의 법인이 생겼다.

한 문장 종족전

사용자가 생물의 행동 원칙을 한 문장으로 쓰면, AI가 실행 가능한 행동 규칙으로 변환하고 2D 생태계에서 경쟁시킨다.

“한 문장으로 생물을 설계하고, 살아남는지는 세계가 결정한다.”

핵심 구조

행동 원칙 작성
AI가 DSL로 컴파일
규칙 검증·제한
2D 자동 시뮬레이션
리플레이·생태 보고서
Natural Language → Behavior DSL

사용자 문장 — 먹이가 가까우면 먹고, 나보다 큰 적을 만나면 도망가며, 혼자 있으면 같은 종족을 찾아간다.

priority:
  - when: food_in_range
    action: move_to_food
  - when: stronger_enemy_nearby
    action: flee
  - when: nearby_allies < 2
    action: move_to_nearest_ally
  - otherwise:
    action: explore

시뮬레이션 결과 — 초반 생존률은 높았으나 집단이 과도하게 뭉치면서 먹이를 빠르게 고갈시켜 43초에 멸종했다.

게임 지표

  • 생존 개체 수
  • 번식 횟수
  • 확보한 영역
  • 전투 승률
  • 먹이 효율과 이동 효율

재미 요소

  • 같은 문장도 환경에 따라 성패가 달라짐
  • 60초 자동 관찰과 결정적 장면 리플레이
  • 종족 간 상성 및 천적 관계
  • 문장 한 부분만 수정해 재도전

시즌 확장

  • 풍요로운 초원
  • 먹이가 부족한 사막
  • 포식자가 존재하는 숲
  • 중앙에만 자원이 생기는 맵
  • 밤낮이 바뀌는 환경

왜 단순 AI 게임 생성과 다른가

AI가 게임을 마음대로 생성하지 않는다

AI는 자연어를 사전에 정의한 센서·조건·행동 집합으로 변환한다. 실제 이동·전투·번식은 결정론적 시뮬레이션 엔진이 수행한다.

문장이 실제 움직임으로 증명된다

사용자가 작성한 전략이 말로만 평가되는 것이 아니라 2D 세계에서 실행된다. 실패 원인도 리플레이로 확인할 수 있다.

MVP 권장 범위

시뮬레이션
  • 40×40 격자 맵
  • 종족 4개 동시 경쟁
  • 개체당 센서 6개, 행동 8개
  • 먹이·번식·전투·수명만 구현
  • 60초 경기와 재현 가능한 랜덤 시드
웹 기능
  • 한 문장 입력과 행동 트리 미리보기
  • Canvas 또는 WebGL 기반 2D 렌더링
  • 속도 조절·일시정지·핵심 장면 이동
  • 생태 보고서와 멸종 원인 분석
  • 종족 코드 공유 및 리그전
위험 문장이 곧 강력한 전략이 된다

사용 가능한 센서·행동 수를 제한하고, 복잡한 문장은 우선순위 슬롯을 소비하도록 해 자연어 길이가 곧 성능이 되지 않게 한다.

위험 AI 변환 결과가 의도와 다르다

실행 전 행동 트리를 사용자에게 보여주고, 문장을 다시 쓰거나 제한된 노드만 수정할 수 있게 한다.

핵심 게임 규칙

편집 제한

한 턴에 기존 사건 한 문장만 바꿀 수 있다. “모두 행복해졌다”처럼 결과를 직접 확정하는 문장은 허용하지 않는다.

복수 목표

동생 생존, 도시 정전 방지, 민서 생존, 보안키 보호 등 여러 조건을 동시에 만족해야 한다.

세계선 비용

편집이 클수록 세계선 불안정도가 올라가며, 새로운 사건이나 역설이 발생할 가능성이 커진다.

권장 구현 구조

백엔드 인과 그래프
  • 사건 노드와 원인·필요조건·결과 엣지
  • 편집된 사건 이후의 영향 범위 계산
  • 목표 조건과 역설 검증
  • 가능한 대체 사건 후보 생성
AI 역할
  • 사용자 문장의 의도와 변화량 해석
  • 인과 그래프 후보 중 자연스러운 사건 선택
  • Diff 설명과 세계선 요약 생성
  • 새로운 모순을 서사적으로 표현

MVP 권장 범위

  • 완성도 높은 고정 시나리오 3개
  • 각 시나리오 12~18개 사건 노드
  • 최대 편집 5회
  • 수정 전·후 타임라인 Diff UI
  • 인과관계 그래프와 목표 달성도
  • 엔딩: “당신이 구한 것 / 잃은 것 / 최초 원인”
가장 큰 위험 자유 생성으로 인과관계가 무너진다

시나리오별 숨은 인과 그래프를 먼저 설계하고, AI는 그래프 밖의 사건을 무제한 생성하지 못하게 해야 한다.

범위 관리 시나리오 수를 욕심내면 완성도가 급락한다

다수의 얕은 시나리오보다, 발표에서 깊게 보여줄 수 있는 2~3개의 정교한 세계선이 낫다.

“최초의 평범한 문장이 마지막에는 어떤 선동 문구가 되었는지 보여준다.”

가장 추천하는 방향

최종 1안은 현실 패치노트다. 자연어 정책을 구조화하고, 여러 시민 유형의 반응을 생성하며, 누적된 정책 간 충돌과 사회 지표를 계산하는 구조는 AI·백엔드·프론트엔드 모두의 기술적 기여를 설명하기 좋다.

AI가 다음 이야기를 써주는 서비스가 아니라, 사용자가 만든 규칙의 약점을 증명하는 서비스.

공통 MVP 진행 순서

어떤 후보를 선택하더라도 AI 프롬프트부터 만들기보다, 먼저 게임 상태와 구조화된 출력 형식을 확정해야 한다.

1단계 · 규칙 검증

종이 프로토타입 또는 고정 응답으로 5번 이상 플레이해 핵심 루프가 실제로 재미있는지 확인한다.

2단계 · 상태 모델

턴, 사용자 입력, 구조화된 AI 출력, 지표, 누적 사건을 JSON Schema로 고정한다.

3단계 · 최소 AI

한 번의 호출로 모든 것을 처리하지 말고 해석·판정·서술 역할을 분리해 테스트한다.

4단계 · 웹 데모

한 시나리오를 처음부터 엔딩까지 완주할 수 있는 수직 슬라이스를 먼저 완성한다.

5단계 · 안정화

프롬프트 인젝션, 구조화 출력 실패, 맥락 누락, 긴 응답을 방어한다.

6단계 · 결과물

리플레이, 패치노트, Diff, 왜곡 타임라인, 리뷰 보고서 등 공유 산출물을 강화한다.

7단계 · 사용자 테스트

완주율, 첫 입력까지 걸린 시간, 재도전률, 결과 공유 의향을 측정한다.

8단계 · 발표 구성

문제 정의보다 “입력 한 줄이 실제 시스템에서 어떻게 변환되는가”를 라이브 데모 중심으로 보여준다.

본 문서는 앞선 아이디어 논의를 바탕으로 팀 의사결정과 MVP 기획에 사용할 수 있도록 재구성한 단일 HTML 문서다. 구체적인 시장 중복 여부와 운영 정책은 최종 주제 선정 후 별도 검증이 필요하다.
